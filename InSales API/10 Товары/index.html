    Товары

    Через API можно создавать товары, управлять их вариантами, ценами и остатками, добавлять изображения и дополнительные поля. В этой статье также описаны привязка товаров к коллекциям, опции покупки и комплекты.

    Список

    GET /admin/products.json возвращает массив товаров. Чтобы узнать количество товаров с теми же фильтрами, используйте GET /admin/products/count.json.

    Параметр per_page задаёт количество товаров на странице. Если передать значение меньше 10, API использует 10. Номер страницы задаётся параметром page.

    GET/admin/products/count.json
    Параметр Описание
    per_page необязательный
    число    		 Количество товаров на странице. При значении меньше 10 API использует 10.
    page необязательный
    число    		 Номер страницы списка товаров.
    filter[title] необязательный
    строка    		 Фильтрация товаров по названию.
    deleted необязательный
    строка    		 true — только архивные товары.
    with_deleted необязательный
    строка    		 true — текущие и архивные товары. 
    GET /admin/products/count.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json

    Ответ · 200

    {"count": 37}

    Для поиска по названию передайте filter[title]. В примере запрашивается первый товар, соответствующий фильтру.

    GET/admin/products.json?per_page=10&filter[title]=iPhone
    Параметр Описание
    per_page необязательный
    число    		 Количество товаров на странице. При значении меньше 10 API использует 10.
    page необязательный
    число    		 Номер страницы.
    filter[title] необязательный
    строка    		 Часть названия. 
    GET /admin/products.json?per_page=10&filter[title]=iPhone
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json

    Ответ · 200

    [
  {
    "id": 673,
    "title": "Apple iPhone 16 Pro Max 1 ТБ",
    "permalink": "apple-iphone-16-pro-max-1-tb"
  }
]

    Чтобы получить несколько товаров по идентификаторам, передайте их в product_ids. Один запрос принимает не более 100 идентификаторов.

    GET/admin/products/by_ids.json?product_ids=561,569
    Параметр Описание
    product_ids обязательный
    строка    		 id товаров через запятую, не больше 100. 
    GET /admin/products/by_ids.json?product_ids=561,569
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json

    Ответ · 200

    [
  {"id": 561, "title": "товар 1"},
  {"id": 569, "title": "товар 2"}
]

    GET /admin/products/999999999.json отвечает 404. Тело при заголовке Accept: application/json остаётся HTML-страницей.

    Скрытые товары (is_hidden: true) входят в список. Архивные товары по умолчанию не возвращаются. Для их получения используйте deleted или with_deleted, как описано в разделе «Удаление и архив».

    Создание

    Для создания товара достаточно передать название и один вариант с ценой. InSales формирует адрес товара (permalink) из названия. Описание сохраняется в виде переданного HTML.

    POST/admin/products.json
    Параметр Описание
    product[title] обязательный
    строка    		 Название. Из него строится permalink.
    product[description] необязательный
    строка    		 Описание, сохраняется как переданный HTML.
    product[short_description] необязательный
    строка    		 Короткое описание.
    product[variants_attributes][][price] обязательный
    число    		 Цена первого варианта.
    product[variants_attributes][][sku] необязательный
    строка    		 Артикул варианта.
    product[variants_attributes][][barcode] необязательный
    строка    		 Штрихкод варианта.
    product[variants_attributes][][quantity] необязательный
    число    		 Остаток варианта. 
    POST /admin/products.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "product": {
    "title": "docs-api-простой",
    "description": "<p>Короткое описание для примера</p>",
    "short_description": "Коротко",
    "variants_attributes": [
      {
        "price": 1500,
        "sku": "DOCS-SIMPLE",
        "barcode": "4600000000017",
        "quantity": 3
      }
    ]
  }
}

    Ответ · 201

    {
  "id": 913,
  "title": "docs-api-простой",
  "permalink": "docs-api-prostoy",
  "is_hidden": false,
  "archived": false,
  "category_id": 1,
  "collections_ids": [],
  "description": "<p>Короткое описание для примера</p>",
  "short_description": "Коротко",
  "variants": [
    {
      "id": 2176487279,
      "sku": "DOCS-SIMPLE",
      "barcode": "4600000000017",
      "price": "1500.0",
      "quantity": 3,
      "quantity_at_warehouse0": "3.0"
    }
  ]
}

    Поле category_id задаёт категорию учёта. Если его не передать, магазин выберет категорию автоматически. Идентификатор коллекции витрины для этого поля не подходит: API вернёт 422 и {"category_id":["Категория удалена или отсутствует."]}. Чтобы добавить товар в коллекцию, используйте отдельный запрос из следующего раздела.

    Если отправить запрос на запись без Content-Type: application/json, API вернёт 422:

    {"message": "incorrect Content-Type, should be application/json"}

    Коллекция

    Чтобы добавить товар в коллекцию, отправьте POST /admin/collects.json. Если коллекция дочерняя, в collections_ids карточки товара появятся и её идентификатор, и идентификатор родительской коллекции.

    Поле position у привязки задаёт положение товара при ручной сортировке в коллекции.

    POST/admin/collects.json
    Параметр Описание
    collect[product_id] обязательный
    число    		 id товара.
    collect[collection_id] обязательный
    число    		 id коллекции.
    collect[position] необязательный
    число    		 Порядок товара в коллекции. 
    POST /admin/collects.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "collect": {
    "product_id": 913,
    "collection_id": 53486014,
    "position": 1
  }
}

    Ответ · 201

    {
  "id": 11029225261,
  "collection_id": 53486014,
  "product_id": 913,
  "position": 1
}
    PUT/admin/collects/11029225261.json
    Параметр Описание
    collect[position] обязательный
    число    		 Новый порядок товара в коллекции. 
    PUT /admin/collects/11029225261.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "collect": {
    "position": 5
  }
}

    Ответ · 200

    {
  "id": 11029225261,
  "collection_id": 53486014,
  "product_id": 913,
  "position": 5
}

    Скрытие

    is_hidden: true убирает товар с витрины и оставляет его в GET /admin/products.json.

    PUT/admin/products/913.json
    Параметр Описание
    product[is_hidden] обязательный
    логический    		 true скрывает товар с витрины, сохраняя его в списке API. false возвращает товар на витрину. 
    PUT /admin/products/913.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "product": {
    "is_hidden": true
  }
}

    Ответ · 200

    {
  "id": 913,
  "title": "docs-api-простой",
  "is_hidden": true,
  "archived": false
}

    Чтобы снова показать товар на витрине, отправьте тот же запрос с "is_hidden": false.

    Удаление и архив

    DELETE /admin/products/:id.json переносит товар в архив и возвращает {"status":"ok"}. После этого чтение карточки без архивных флагов возвращает 404 с HTML-страницей.

    Если товара с указанным идентификатором нет, DELETE также возвращает 200 и {"status":"ok"}. По ответу на удаление нельзя определить, существовал ли товар.

    По умолчанию список не содержит архивных товаров. С deleted=true API возвращает только архивные товары с archived: true. С with_deleted=true возвращаются и текущие, и архивные товары. Ниже показана одна запись из списка с deleted=true.

    GET/admin/products.json?deleted=true&per_page=250
    Параметр Описание
    deleted необязательный
    строка    		 true возвращает только архивные товары с archived: true.
    with_deleted необязательный
    строка    		 true возвращает текущие и архивные товары.
    per_page необязательный
    число    		 Размер страницы. 
    GET /admin/products.json?deleted=true&per_page=250
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json

    Ответ · 200

    [
  {
    "id": 977,
    "title": "docs-api-архив",
    "archived": true
  }
]

    Дополнительное поле товара

    Пустой массив product_field_values означает, что у товара нет значений дополнительных полей. Сначала создайте само поле; для текстового поля передайте type: ProductField::TextField.

    Затем запишите значение в товар через product_field_values_attributes. Оно будет возвращаться при чтении карточки товара.

    POST/admin/product_fields.json
    Параметр Описание
    product_field[title] обязательный
    строка    		 Название поля.
    product_field[handle] необязательный
    строка    		 Системное имя.
    product_field[type] обязательный
    строка    		 Тип поля. Для текста — ProductField::TextField. 
    POST /admin/product_fields.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "product_field": {
    "title": "docs-api Комментарий",
    "handle": "docs_api_comment",
    "type": "ProductField::TextField"
  }
}

    Ответ · 201

    {
  "id": 4586434,
  "handle": "docs_api_comment",
  "type": "ProductField::TextField",
  "title": "docs-api Комментарий"
}
    PUT/admin/products/985.json
    Параметр Описание
    product[product_field_values_attributes][][product_field_id] обязательный
    число    		 id дополнительного поля.
    product[product_field_values_attributes][][value] обязательный
    строка    		 Значение дополнительного поля. Если значений нет, в карточке возвращается пустой product_field_values. 
    PUT /admin/products/985.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "product": {
    "product_field_values_attributes": [
      {
        "product_field_id": 4586434,
        "value": "пример"
      }
    ]
  }
}

    Ответ · 200

    {
  "id": 985,
  "product_field_values": [
    {"id": 895989818, "product_field_id": 4586434, "value": "пример"}
  ]
}

    Параметры

    Параметр описывает товар целиком, например его материал, состав или длину. В API параметр представлен свойством property и его значением characteristic. При создании или обновлении товара передайте название свойства и его значение в properties_attributes.

    Размер и цвет, от которых зависят варианты товара, задаются свойствами вариантов. Гравировка или подарочная упаковка могут быть опциями покупки: у каждого значения такой опции есть своя цена.

    Чтобы прочитать параметры товара, запросите GET /admin/products/:id.json. Массив properties содержит свойства, а characteristics — их значения. Поле property_id у значения указывает на id свойства. Название значения хранится в title.

    Запись по названиям

    Если свойства или значения с переданным названием ещё нет в магазине, API создаёт его. Несколько элементов properties_attributes с одинаковым title задают несколько значений одного свойства. В ответе будет одно свойство и несколько значений с одинаковым property_id.

    POST/admin/products.json
    Параметр Описание
    product[title] обязательный
    строка    		 Название товара.
    product[variants_attributes][][price] обязательный
    число    		 Цена варианта.
    product[properties_attributes][][title] обязательный
    строка    		 Название параметра. Повтор названия добавляет ещё одно значение.
    product[properties_attributes][][value] обязательный
    строка    		 Значение параметра. 
    POST /admin/products.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "product": {
    "title": "docs-api-параметры",
    "variants_attributes": [
      {
        "price": 500,
        "sku": "DOCS-PROP"
      }
    ],
    "properties_attributes": [
      {
        "title": "docs-api Материал",
        "value": "Хлопок"
      },
      {
        "title": "docs-api Состав",
        "value": "90% хлопок"
      },
      {
        "title": "docs-api Состав",
        "value": "10% эластан"
      }
    ]
  }
}

    Ответ · 201

    {
  "id": 929,
  "title": "docs-api-параметры",
  "properties": [
    {"id": 61541236, "title": "docs-api Материал", "permalink": "docs-api-material"},
    {"id": 61541237, "title": "docs-api Состав", "permalink": "docs-api-sostav"}
  ],
  "characteristics": [
    {"id": 785, "property_id": 61541236, "title": "Хлопок", "permalink": "hlopok"},
    {"id": 793, "property_id": 61541237, "title": "90% хлопок", "permalink": "90-hlopok"},
    {"id": 801, "property_id": 61541237, "title": "10% эластан", "permalink": "10-elastan"}
  ]
}

    Полный список при обновлении

    При обновлении properties_attributes заменяет весь набор параметров товара. Связи со значениями, которые не вошли в запрос, удаляются.

    Чтобы добавить параметр и сохранить существующие, передайте в properties_attributes как прежние пары «свойство — значение», так и новую.

    PUT/admin/products/929.json
    Параметр Описание
    product[properties_attributes][][title] обязательный
    строка    		 Название параметра. Передавайте полный набор пар «свойство — значение», который должен остаться у товара.
    product[properties_attributes][][value] обязательный
    строка    		 Значение параметра. 
    PUT /admin/products/929.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "product": {
    "properties_attributes": [
      {
        "title": "docs-api Материал",
        "value": "Лён"
      }
    ]
  }
}

    Ответ · 200

    {
  "id": 929,
  "properties": [
    {"id": 61541236, "title": "docs-api Материал"}
  ],
  "characteristics": [
    {"id": 809, "property_id": 61541236, "title": "Лён", "permalink": "lyon"}
  ]
}

    Если не передать properties_attributes, набор параметров товара не изменится.

    Одна пара по id

    Чтобы добавить одну пару по идентификаторам и сохранить существующие, используйте product_characteristics_attributes. Передайте property_id и characteristic_id.

    PUT/admin/products/929.json

    Варианты

    Вариант — это сочетание значений свойств вроде размера и цвета, со своей ценой, остатком, артикулом и штрихкодом. Справочник свойств (option_name) — в свойствах вариантов.     Внешний идентификатор

    external_id — идентификатор варианта во внешней системе. Его пишут в уже созданный вариант запросом PUT /admin/products/:product_id/variants/:id.json.

    При создании товара данные вариантов передаются в variants_attributes: цена, артикул, остаток, вес и габариты. Поле external_id в этом вложенном объекте не поддерживается. Если передать его при создании товара, API вернёт 422 и укажет недопустимый ключ:

    {"variants_attributes": ["undefined keys [\"external_id\"]"]}

    Обновление варианта с "external_id": "1c-200" возвращает 200. Значение сохраняется у варианта, но не включается в его JSON-ответ.

    Остаток

    quantity — остаток варианта. Остаток на складе передаётся полем quantity_at_warehouseN. Число N — это array_index склада из GET /admin/warehouses.json. У единственного склада индекс 0, поле называется quantity_at_warehouse0.

    Если в магазине один склад, quantity и quantity_at_warehouse0 описывают один остаток: изменение любого из этих полей меняет оба. Остаток склада возвращается строкой, например "7.0". Работа с несколькими складами и суммарным остатком описана в разделе «Склады».

    Групповое обновление

    PUT /admin/products/variants_group_update.json меняет цены и остатки сразу у нескольких вариантов. В теле — массив variants, у каждого элемента обязателен id:

    {"variants": [{"id": 2176487279, "price": 1900}]}

    API сразу возвращает 200 с пустым массивом []. Изменения применяются не сразу. Чтобы проверить новые цены и остатки, повторно запросите варианты после завершения обновления.

    Типы цен

    Тип цены позволяет хранить у варианта дополнительную цену. Методы доступны, если эта возможность входит в тариф магазина. На обычном тарифе можно создать не более 20 типов цен.

    POST /admin/price_kinds.json отвечает 201. price_index начинается с 1. variant_price_method_name для первого типа — price2: в варианте это поле price2. Следующий тип получает следующий индекс и поле price3. Повтор названия отвечает 422:

    {"title":["уже существует"]}

    PUT /admin/price_kinds/:id.json меняет title и show_in_lists.

    POST/admin/price_kinds.json
    Параметр Описание
    price_kind[title] обязательный
    строка    		 Название типа цены. Уникально в магазине.
    price_kind[show_in_lists] необязательный
    логический    		 Показывать цену в списках. 
    POST /admin/price_kinds.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "price_kind": {
    "title": "docs-api Опт",
    "show_in_lists": false
  }
}

    Ответ · 201

    {
  "id": 1,
  "price_index": 1,
  "title": "docs-api Опт",
  "show_in_lists": false,

    Для записи дополнительной цены передайте в вариант поле, указанное в variant_price_method_name. Базовая цена price возвращается строкой, дополнительная — числом. Массив prices содержит дополнительные цены в порядке типов.

    Изображения

    Чтобы добавить изображение к товару, используйте POST /admin/products/:product_id/images.json. Пока InSales обрабатывает файл, image_processing равен true, а URL изображений указывают на /images/loading.gif. Имя файла в ответе уже соответствует загруженному файлу.

    Адрес изображения

    src — публичный адрес файла. Магазин скачивает изображение по этому адресу, поэтому адрес должен открываться из интернета. Если файл по адресу скачать нельзя, ответ 422:

    {"image": ["Не заполнены обязательные поля"], "src": ["Недопустимый URL"]}
    POST/admin/products/985/images.json
    Параметр Описание
    image[src] обязательный
    строка    		 Адрес изображения в интернете. 
    POST /admin/products/985/images.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "image": {
    "src": "https://upload.wikimedia.org/wikipedia/commons/c/ca/1x1.png"
  }
}

    Ответ · 201

    {
  "id": 377,
  "product_id": 985,
  "position": 1,
  "image_processing": true,
  "filename": "1x1.png",

  "original_url": "/images/loading.gif"
}

    Сопутствующие

    Чтобы назначить сопутствующие товары, отправьте запрос на /admin/products/:id/supplementaries.json с массивом supplementary_ids. При сохранении API возвращает {"status":"ok"}. Список сопутствующих товаров возвращается массивом объектов с полем id.

    Опция покупки

    Комплект

    Чтобы создать комплект, передайте при создании товара "bundle": true и состав в product_bundle_components_attributes. Для каждой составляющей укажите variant_id другого товара и количество. Цену комплекта задайте в его собственном варианте через variants_attributes.

    POST/admin/products.json
    Параметр Описание
    product[title] обязательный
    строка    		 Название комплекта.
    product[bundle] обязательный
    логический    		 true помечает товар как комплект.
    product[variants_attributes][][price] обязательный
    число    		 Цена комплекта.
    product[product_bundle_components_attributes][][variant_id] обязательный
    число    		 id варианта в составе.
    product[product_bundle_components_attributes][][quantity] обязательный
    число    		 Сколько штук этого варианта входит в комплект. 
    POST /admin/products.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "product": {
    "title": "docs-api-комплект",
    "bundle": true,
    "variants_attributes": [
      {
        "price": 40
      }
    ],
    "product_bundle_components_attributes": [
      {
        "variant_id": 2176487279,
        "quantity": 1
      },
      {
        "variant_id": 2176487286,
        "quantity": 1
      }
    ]
  }
}

    Ответ · 201

    {
  "id": 969,
  "title": "docs-api-комплект",
  "bundle": true,
  "product_bundle_components": [
    {"id": 2, "variant_id": 2176487279, "quantity": "1.0", "product_id": 913, "free": false},
    {"id": 3, "variant_id": 2176487286, "quantity": "1.0", "product_id": 961, "free": false}
  ],
  "variants": [
    {"id": 2176487287, "price": "40.0"}
  ]
}

    Признак bundle можно задать только при создании товара. Если обновить обычный товар, передав "bundle": true и состав комплекта, API вернёт 200, но товар не станет комплектом. В ответе bundle будет равен null, а product_bundle_components — пустому массиву.
