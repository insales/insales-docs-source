    Темы, ассеты и файлы

    Для чтения и изменения тем, ассетов и типов виджетов приложению нужно право на дизайн. Для работы с разделом «Контент — Файлы» нужно право на файлы, для панелей блоков — право на блоки.

    Если нужного права нет, ответ 403:

    {"status":"error","message":"Недостаточно прав для операции"}

    Новую тему через этот API создать нельзя: POST /admin/themes.json отвечает 404. Скачать тему архивом нельзя: GET /admin/themes/:id/export.json отвечает 404.

    Файлы темы и файлы раздела «Контент — Файлы» имеют разные адреса на витрине. В шаблоне используйте фильтр asset_url для файла темы и file_url для файла из раздела «Контент — Файлы».

    Список тем

    GET /admin/themes.json возвращает массив тем, которые можно открыть. В объект входят название, признак публикации, язык, версия ассетов и текст последней ошибки темы.

    GET/admin/themes.json
    GET /admin/themes.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json

    Ответ · 200

    [
  {
    "id": 1,
    "title": "Пользовательская",
    "description": null,
    "is_published": true,
    "is_mobile": null,
    "language_id": 1,
    "assets_version": 1651223995,
    "errors_text": null,
    "created_at": "2026-10-19T21:43:37.000+03:00",
    "updated_at": "2026-10-21T22:17:41.000+03:00"
  }
]

    is_published: true — тема включена на витрине. language_id — язык темы. assets_version входит в путь файлов темы. errors_text — текст последней ошибки темы. У темы без ошибки поле равно null.

    GET /admin/themes/999999999.json отвечает 404. Тело при заголовке Accept: application/json остаётся HTML-страницей.

    При чтении одной темы API возвращает тот же набор полей.

    GET/admin/themes/1.json
    Параметр Описание
    id обязательный
    число    		 id темы в пути. 
    GET /admin/themes/1.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json

    Ответ · 200

    {
  "id": 1,
  "title": "Пользовательская",
  "description": null,
  "is_published": true,
  "is_mobile": null,
  "language_id": 1,
  "assets_version": 1651223995,
  "errors_text": null,
  "created_at": "2026-10-19T21:43:37.000+03:00",
  "updated_at": "2026-10-21T22:17:41.000+03:00"
}

    Название и описание

    PUT /admin/themes/:id.json сохраняет title и description. Ответ — {"status":"ok"}, саму тему нужно прочитать отдельным GET. description: null очищает описание.

    PUT/admin/themes/1.json
    Параметр Описание
    id обязательный
    число    		 id темы в пути.
    theme[title] необязательный
    строка    		 Название темы.
    theme[description] необязательный
    строка    		 Описание. `null` очищает поле. 
    PUT /admin/themes/1.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "theme": {
    "title": "Пользовательская",
    "description": "docs probe"
  }
}

    Ответ · 200

    {"status":"ok"}

    Чтобы изменить цвета, шрифты и пресеты, обновите файл settings_data.json. Эти настройки не передаются в запросе на изменение темы. Подробнее — в разделе «Настройки темы».

    Публикация

    PUT /admin/themes/:id/publish.json публикует тему. Повторный вызов для уже опубликованной темы тоже отвечает {"status":"ok"}.

    PUT/admin/themes/1/publish.json
    Параметр Описание
    id обязательный
    число    		 id темы в пути. 
    PUT /admin/themes/1/publish.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{}

    Ответ · 200

    {"status":"ok"}

    Удаление

    Если отправить DELETE /admin/themes/:id.json для опубликованной основной темы, API вернёт {"status":"ok"}, но тема останется в списке.

    DELETE/admin/themes/1.json
    Параметр Описание
    id обязательный
    число    		 id темы в пути. 
    DELETE /admin/themes/1.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json

    Ответ · 200

    {"status":"ok"}

    После ответа на удаление проверьте тему отдельным запросом. Ответ {"status":"ok"} подтверждает принятие запроса, но не гарантирует удаление записи.

    Ассеты темы

    Ассет — файл внутри темы: шаблон, сниппет, картинка, стиль, скрипт или JSON из каталога config. Адрес: /admin/themes/:theme_id/assets.json.

    type при создании:

    Тип Что это Имя в запросе
    Asset::Template Шаблон страницы. К имени дописывается .liquid. product.docs_api становится product.docs_api.liquid
    Asset::Snippet Сниппет. К имени дописывается .liquid. docs_api_note становится docs_api_note.liquid
    Asset::Media Картинка, CSS, JS и прочие файлы в корне темы. Имя как есть, с расширением: docs-api.png
    Asset::Configuration JSON настроек в config. docs-api.json, settings_data.json

    Список возвращает идентификатор, тип, имя, человекочитаемое имя, адрес и version — время изменения в формате Unix. Содержимое файлов в список не включается.

    GET/admin/themes/1/assets.json
    Параметр Описание
    theme_id обязательный
    число    		 id темы в пути. 
    GET /admin/themes/1/assets.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json

    Ответ · 200

    [
  {
    "id": 97,
    "human_readable_name": "Товар",
    "asset_url": "/assets/1/1/1/1651223995/templates/product.liquid",
    "inner_file_name": "product.liquid",
    "type": "Asset::Template",
    "version": 1792435418
  },
  {
    "id": 177,
    "human_readable_name": "theme.css",
    "asset_url": "/assets/1/1/1/1651223995/theme.css",
    "inner_file_name": "theme.css",
    "type": "Asset::Media",
    "version": 1792435421
  }
]

    Список содержит все файлы темы без их содержимого. Поле asset_url задаёт путь к файлу на витрине без хоста. Путь включает значение assets_version темы.

    При чтении одного Liquid-файла API дополнительно возвращает поле content. Для CSS, JS, изображений и JSON это поле в ответ не включается.

    GET/admin/themes/1/assets/113.json
    Параметр Описание
    theme_id обязательный
    число    		 id темы в пути.
    id обязательный
    число    		 id ассета в пути. 
    GET /admin/themes/1/assets/113.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json

    Ответ · 200

    {
  "id": 113,
  "human_readable_name": "head.liquid",
  "asset_url": "/assets/1/1/1/1651223995/snippets/head.liquid",
  "inner_file_name": "head.liquid",
  "type": "Asset::Snippet",
  "version": 1792435418,
  "content": "<!-- meta -->\n<meta charset=\"UTF-8\" />\n"
}

    У CSS, JS, картинки и JSON тот же GET возвращает метаданные без content.

    Чтобы получить содержимое любого файла, используйте отдельный адрес .../raw.json. API возвращает само содержимое: текст для JSON или CSS, байты файла для изображения.

    GET/admin/themes/1/assets/153/raw.json
    Параметр Описание
    theme_id обязательный
    число    		 id темы в пути.
    id обязательный
    число    		 id ассета в пути. 
    GET /admin/themes/1/assets/153/raw.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json

    Ответ · 200

    {
  "current": "custom",
  "generation": 4,
  "presets": {
    "custom": {
      "color-btn-bg": "#0073E6"
    }
  }
}

    Например, через этот адрес можно прочитать settings_data.json. Запрос к .../raw без суффикса .json возвращает 404 с пустым телом.

    При чтении изображения в формате .xml ответ дополнительно содержит attachment — файл в Base64. В JSON этого поля нет; для получения байтов изображения используйте raw.json.

    Создание ассета

    Для создания ассета отправьте POST /admin/themes/:theme_id/assets.json. Заголовок Content-Type: application/json обязателен. Без него API вернёт 422 и {"message":"incorrect Content-Type, should be application/json"}.

    Чтобы создать сниппет, передайте его текст в content. InSales автоматически добавит расширение .liquid к имени.

    POST/admin/themes/1/assets.json
    Параметр Описание
    theme_id обязательный
    число    		 id темы в пути.
    asset[type] обязательный
    строка    		 `Asset::Snippet`.
    asset[name] обязательный
    строка    		 Имя без `.liquid`.
    asset[content] обязательный
    строка    		 Текст сниппета. 
    POST /admin/themes/1/assets.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "asset": {
    "type": "Asset::Snippet",
    "name": "docs_api_note",
    "content": "<p>docs-api</p>"
  }
}

    Ответ · 201

    {
  "id": 1241,
  "human_readable_name": "docs_api_note.liquid",
  "asset_url": "/assets/1/1/1/1651223995/snippets/docs_api_note.liquid?1792609806",
  "inner_file_name": "docs_api_note.liquid",
  "type": "Asset::Snippet",
  "version": 1792609806
}

    Повтор с тем же именем — 422:

    {"inner_file_name":["Файл с именем docs_api_note.liquid уже существует"]}

    Невалидный Liquid отвечает 422:

    {"inner":["Ошибка синтаксиса: Liquid syntax error (line 1): [:end_of_string] is not a valid expression in \"\""]}

    Неизвестный type — 422, в теле одновременно «Не заполнены обязательные поля» у inner и «имеет неверное значение» у type.

    Свой шаблон товара называется product.ИМЯ. В ответе human_readable_name — «Товар: ИМЯ». Так же создаются page.ИМЯ («Страница: ИМЯ») и collection.ИМЯ («Категория: ИМЯ»).

    POST/admin/themes/1/assets.json
    Параметр Описание
    theme_id обязательный
    число    		 id темы в пути.
    asset[type] обязательный
    строка    		 `Asset::Template`.
    asset[name] обязательный
    строка    		 Тип страницы, точка и имя шаблона.
    asset[content] обязательный
    строка    		 Liquid-текст шаблона. 
    POST /admin/themes/1/assets.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "asset": {
    "type": "Asset::Template",
    "name": "product.docs_api",
    "content": "<h1>{{ product.title }}</h1>"
  }
}

    Ответ · 201

    {
  "id": 1249,
  "human_readable_name": "Товар: docs_api",
  "asset_url": "/assets/1/1/1/1651223995/templates/product.docs_api.liquid?1792609807",
  "inner_file_name": "product.docs_api.liquid",
  "type": "Asset::Template",
  "version": 1792609807
}

    Чтобы загрузить изображение или другой бинарный файл, передайте его содержимое в Base64 в поле attachment. В filename укажите имя файла — оно будет возвращаться в поле name.

    POST/admin/themes/1/assets.json
    Параметр Описание
    theme_id обязательный
    число    		 id темы в пути.
    asset[type] обязательный
    строка    		 `Asset::Media`.
    asset[name] обязательный
    строка    		 Имя файла с расширением.
    asset[filename] обязательный
    строка    		 То же имя: по нему определяется тип Base64.
    asset[attachment] обязательный
    строка    		 Файл в Base64. 
    POST /admin/themes/1/assets.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "asset": {
    "type": "Asset::Media",
    "name": "docs-api.png",
    "filename": "docs-api.png",
    "attachment": "iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg=="
  }
}

    Ответ · 201

    {
  "id": 1257,
  "human_readable_name": "docs-api.png",
  "asset_url": "/assets/1/1/1/1651223995/docs-api.png?1792609808",
  "inner_file_name": "docs-api.png",
  "type": "Asset::Media",
  "version": 1792609808
}

    Вместо содержимого в Base64 можно передать публичный URL в src со схемой http или https. Для адреса внутренней сети API возвращает 422: ошибку «Недопустимый URL» у src и «Не заполнены обязательные поля» у inner.

    CSS и JSON создаются тем же полем content. Для CSS тип — Asset::Media, для JSON — Asset::Configuration. raw.json возвращает текст файла как есть.

    Изменение и переименование

    Чтобы заменить содержимое ассета, передайте новый текст в content запросом PUT. В JSON-ответе текст файла не возвращается. Проверьте результат через GET для Liquid-файла или через raw.json для остальных типов.

    PUT/admin/themes/1/assets/1241.json
    Параметр Описание
    theme_id обязательный
    число    		 id темы в пути.
    id обязательный
    число    		 id ассета в пути.
    asset[content] обязательный
    строка    		 Новый текст файла. 
    PUT /admin/themes/1/assets/1241.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "asset": {
    "content": "<p>docs-api updated</p>"
  }
}

    Ответ · 200

    {
  "id": 1241,
  "human_readable_name": "docs_api_note.liquid",
  "asset_url": "/assets/1/1/1/1651223995/snippets/docs_api_note.liquid",
  "inner_file_name": "docs_api_note.liquid",
  "type": "Asset::Snippet",
  "version": 1792609807
}

    Для переименования используйте отдельный путь .../rename.json. Передайте новое имя в поле new_name.

    PUT/admin/themes/1/assets/1241/rename.json
    Параметр Описание
    theme_id обязательный
    число    		 id темы в пути.
    id обязательный
    число    		 id ассета в пути.
    asset[new_name] обязательный
    строка    		 Новое имя файла. 
    PUT /admin/themes/1/assets/1241/rename.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "asset": {
    "new_name": "docs_api_note_renamed.liquid"
  }
}

    Ответ · 200

    {
  "id": 1241,
  "human_readable_name": "docs_api_note_renamed.liquid",
  "asset_url": "/assets/1/1/1/1651223995/snippets/docs_api_note_renamed.liquid?1792609807",
  "inner_file_name": "docs_api_note_renamed.liquid",
  "type": "Asset::Snippet",
  "version": 1792609807
}

    Стандартный шаблон, например product.liquid, так не переименовывается. Ответ 422:

    {"inner_file_name":["Нельзя переименовать стандартный шаблон"]}

    Удаление ассета

    DELETE возвращает 200 с пустым телом и при успешном удалении, и когда файл удалить нельзя. Чтобы проверить результат, запросите файл отдельным GET.

    Сниппет, свой шаблон, картинка и CSS после такого ответа читаются как 404. Стандартный product.liquid остаётся на месте. Файл типа Asset::Configuration, в том числе свой JSON-файл настроек и settings_data.json, тоже остаётся: GET после DELETE по-прежнему 200.

    DELETE/admin/themes/1/assets/1241.json
    Параметр Описание
    theme_id обязательный
    число    		 id темы в пути.
    id обязательный
    число    		 id ассета в пути. 
    DELETE /admin/themes/1/assets/1241.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json

    Ответ · 200

    Тело пустое.

    Настройки темы

    Цвета, шрифты и текущий пресет хранятся в settings_data.json — ассете типа Asset::Configuration. Чтобы прочитать файл, используйте .../raw.json: запрос метаданных не возвращает content.

    Для сохранения передайте весь JSON файла строкой в content запросом PUT. API вернёт метаданные ассета. Проверьте сохранённый текст повторным запросом к raw.json.

    PUT/admin/themes/1/assets/153.json
    Параметр Описание
    theme_id обязательный

    Перед сохранением получите весь файл через raw.json, измените нужные ключи и передайте полный JSON в content. Если передать только часть файла, остальные настройки пресета будут удалены.

    Перед сохранением settings_data.json проверяйте синтаксис JSON: API принимает даже невалидный JSON со статусом 200, после чего файл не удаётся разобрать. Для settings.json и других JSON-ассетов такое тело отклоняется со статусом 422, а файл остаётся прежним:

    {"content":["Невалидный json"]}

    Рядом в теме лежат:

    • settings.json — описание полей редактора. Невалидный JSON отклоняется.
    • messages.json — тексты по языкам. Обновляется тем же PUT с полным JSON.
    • setup.json — состав блоков темы, в том числе block_lists. Читается через raw.json. Метода для панелей виджетов страницы в этом API нет, см. ниже.

    Файлы аккаунта

    Ресурс /admin/files.json позволяет работать с разделом «Контент — Файлы». В ответе возвращаются id, created_at и absolute_url. Отдельного поля с именем нет: имя файла находится в конце absolute_url.

  },

    Свой шаблон страницы

    Чтобы назначить собственный шаблон товару, странице или категории, запишите в custom_template часть имени файла между первой точкой и .liquid. Например, для product.docs_api.liquid передайте docs_api. Одного создания файла недостаточно для его назначения.

    API сохраняет custom_template, даже если соответствующего файла нет в теме.

    PUT /admin/products/681.json

Accept: application/json

{
  "product": {
    "custom_template": "docs_api"

    {

    Виджеты темы

    Для работы с типами виджетов темы используйте /admin/themes/:theme_id/widget_types.json. Список возвращает только собственные типы указанной темы; системные типы не включаются.

    Размещать виджеты на странице, получать список виджетов страницы и панели header / content / footer через этот API нельзя. Запросы GET /admin/themes/1/widgets.json, GET /admin/widget_lists.json и GET /admin/widgets.json возвращают 404.

    Виджет в карточке заказа или товара бэк-офиса — другой ресурс, виджеты приложения.

    При создании типа виджета передавайте поля на верхнем уровне JSON. Если вложить их в widget_type, API вернёт 422: ключ будет отмечен как неизвестный, а обязательные поля — как пропущенные.

    page_kinds — массив из all, index, collection, product, cart, page, search, blog, article, compare, favorite, shared_cart. Чужое значение даёт 422: {"page_kinds":{"0":["is not valid"]}}.

    widget_list_kinds — массив из header, before_content, content, sidebar, after_content, footer, outside, top_panel, bottom_panel. Чужое значение: {"widget_list_kinds":{"0":["is not valid"]}}.

    widget_category_handle — handle существующей категории, например benefits. Неизвестная категория: 422, widget_category_id — «Не заполнены обязательные поля».

    Панели блоков

    /admin/block_lists.json возвращает панели блоков магазина. У панели есть имя, liquid_name и block_template_id. Чтобы получить её состав, используйте /admin/block_lists/:id/block_list_items.json: у каждого элемента есть block_id и position.

    GET/admin/block_lists.json

    "id": 1,
    "block_list_id": 1,
    "block_id": 1,
    "position": 1
  },
  {
    "id": 9,
    "block_list_id": 1,
    "block_id": 9,

    Создать панель через POST /admin/block_lists.json с name и liquid_name нельзя: API возвращает 404 со страницей «Couldn't find BlockList without an ID». Изменение панели через PUT в JSON возвращает 406; панель не изменяется.

    Получить список блоков через GET /admin/blocks.json нельзя: API возвращает 404. Запрос POST /admin/blocks.json с названием и текстом возвращает 200 и {"status":"error","errors":{}}. В формате XML тот же запрос возвращает 422 с пустым <errors/>. Отдельного метода чтения блока нет.

    Для чтения состава блоков поколения 4, который отображается в редакторе темы, получите файл setup.json через raw.json. Методы панелей блоков не возвращают этот состав. Разместить виджет на панели через публичный API нельзя.
