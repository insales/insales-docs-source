    Заказы и клиенты

    Для работы с заказами и клиентами используйте авторизацию приложения в API бэк-офиса. Вход покупателя на витрину через session.json не даёт доступа к этим методам. Чтобы получить заказы конкретного клиента, передайте client_id в GET /admin/orders.json.

    Сверка списков по updated_since и from_id — в изменившихся данных. Скидка на отдельные строки — в частичных скидках. Скидка внешней системы — в внешних скидках.

    Заказы

    В пути к заказу используется id — его идентификатор в API. Поле number содержит номер, который магазин показывает покупателю. Эти значения независимы: например, у заказа с id: 1 может быть number: 1000, а следующий заказ получит номер 1001.

    GET /admin/orders/1000.json, где 1000 — номер, а не id, отвечает 404. Тело при Accept: application/json остаётся HTML-страницей.

    Карточка заказа содержит поля заказа, строки order_lines, клиента client, адрес shipping_address и скидки discounts. Поле discount дублирует первую скидку из массива.

    У строки заказа есть sale_price, full_sale_price, total_price, full_total_price, quantity, variant_id, product_id и bundle_id. Вложенный объект client содержит меньше данных, чем карточка клиента: в нём нет default_address, client_tags и full_name.

    custom_status — объект с permalink и title. fulfillment_status — системный статус исполнения: new, accepted, approved, dispatched, delivered, returning, declined, returned. financial_status — оплата: pending, paid, partially_paid.

    Список и количество заказов

    GET /admin/orders.json возвращает массив заказов. По умолчанию на странице 25 записей, отсортированных по убыванию id. Если per_page больше 100, API использует 100. Значение per_page=1 возвращает одну запись, per_page=0 — пустой массив.

    Нумерация page начинается с 1. При page=0 API возвращает 422 и {"message":"page должен иметь значение, большее 0"}.

    GET /admin/orders/count.json возвращает количество заказов, соответствующих переданным фильтрам: {"count": N}.

    GET/admin/orders.json?per_page=1

    page необязательный
    число    		 Номер страницы, начиная с 1.

    Фильтрация

    Чтобы найти заказ по номеру, задайте одинаковые number_from и number_to. Для диапазона укажите разные границы. Параметр number не фильтрует список.

    from_number оставляет заказы с номером больше либо равным переданному. Номер больше последнего даёт пустой массив.

    client_id ограничивает список заказами одного клиента. Для нескольких идентификаторов повторите параметр ids[]. Параметры fulfillment_status, delivery_variant_id и payment_gateway_id требуют точного совпадения. Параметр q использует поиск магазина; строка, для которой нет совпадений, возвращает [].

    С status=open возвращаются заказы в работе, в том числе доставленные, но ещё не оплаченные. С status=closed возвращаются отменённые, возвращённые, а также доставленные и оплаченные заказы.

    custom_status сравнивает permalink пользовательского статуса. Несколько значений передаются повторением параметра.

    Одиночный параметр financial_status=paid возвращает оплаченные заказы. Любое другое одиночное значение, включая pending и partially_paid, возвращает все заказы со статусом оплаты, отличным от paid. Чтобы выбрать точные статусы, используйте массив financial_status[].

    API принимает created_at_from и created_at_to со статусом 200, но запрос за календарный день может вернуть пустой список, даже если в этот день есть заказы. Для чтения изменений используйте updated_since.

    При заданном updated_since заказы сортируются по возрастанию updated_at, затем по id. Поэтому при per_page=1 возвращается самый старый из подходящих заказов. В следующем запросе передайте его updated_at как updated_since, а id — как from_id: этот заказ повторно не вернётся. Последовательность обхода описана в статье «Получение только изменившихся данных».

    Чтобы получить заказы клиента за период, ограничьте список параметром client_id. Дату создания проверяйте по created_at полученных заказов; если нужен период изменения, используйте updated_since.

    Архив

    По умолчанию архивные заказы не возвращаются ни в списке, ни при чтении карточки. Запрос к карточке архивного заказа возвращает 404 с HTML-страницей.

    Параметр deleted=true возвращает только архивные заказы, with_deleted=true — текущие и архивные. У архивного заказа archived равен true. Эти флаги применяются к списку, карточке и подсчёту заказов.

    GET/admin/orders/2.json?with_deleted=true
    Параметр Описание
    id обязательный
    число    		 Идентификатор заказа.
    with_deleted необязательный
    строка    		 true — отдать заказ и из архива.
    deleted необязательный
    строка    		 true — только архивный заказ. 
    GET /admin/orders/2.json?with_deleted=true
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json

    Ответ · 200

    {"id": 2, "number": 1001, "archived": true}

    Создание с товаром

    Для создания заказа передайте объект order в POST /admin/orders.json. Строки заказа задаются через order_lines_attributes. Поле order_lines при создании игнорируется: если строки не заданы, API вернёт 422 и сообщение «Заказ должен содержать хотя бы одну позицию».

    Для строки достаточно указать variant_id и quantity. Если передать только product_id, InSales выберет первый вариант товара. Если передать sale_price, это значение станет ценой строки и будет использоваться при расчёте суммы заказа.

    Передайте адрес объектом shipping_address, указав населённый пункт в full_locality_name. В сообщениях об ошибках это поле называется «Населенный пункт». Отдельные город и регион не заменяют full_locality_name. Если телефон и согласие на обработку персональных данных обязательны в настройках магазина, их тоже нужно передать.

    Параметры delivery_variant_id и payment_gateway_id выбирают способы доставки и оплаты. При создании заказа цена доставки берётся из настроек способа.

    Для внешней доставки передайте тариф и точку самовывоза в delivery_info_attributes: поля tariff_id, price, title и outlet. Для DeliveryVariant::PickUp укажите в outlet координаты latitude и longitude. Без них API вернёт 422 и сообщение «Не выбрана точка самовывоза».

    Поля способов описаны в разделах «Доставка» и «Способы оплаты». Чтобы отключить письма клиенту и магазину, используйте соответственно not_send_email_to_client и not_send_email_to_account.

    Клиента можно передать вложенным объектом client или указать идентификатор существующего клиента в client_id. Во вложенном объекте сохраняются имя, почта, телефон и согласие. Чтобы записать фамилию и отчество, сначала создайте клиента отдельным запросом, затем передайте его client_id в заказ.

    Создание с комплектом

    Для заказа комплекта передайте в строке variant_id комплекта. При сохранении InSales заменяет эту строку составляющими. У каждой из них bundle_id содержит идентификатор товара-комплекта. Количество составляющей равно её количеству в комплекте, умноженному на количество комплектов в заказе. Сумма цен составляющих равна цене комплекта.

    Тот же вариант может быть добавлен в заказ отдельной строкой. У неё будет такой же variant_id, как у составляющей комплекта, но пустой bundle_id. Поэтому для скидки выбирайте строку по order_lines[].id, как описано в статье «Частичные скидки в заказе».

    Комплект ниже собран из варианта за 100 и двух штук варианта за 1, цена комплекта 90. В заказе одна штука комплекта и одна отдельная штука первого варианта.

    Статусы

    Статус financial_status: "paid" заполняет paid_at и устанавливает paid_amount по текущей сумме заказа. При partially_paid заказ не считается полностью оплаченным, а paid_at сбрасывается. Если затем уменьшить сумму заказа, уже записанный paid_amount автоматически не уменьшится.

    fulfillment_status переводит заказ в системный статус и подставляет permalink статуса по умолчанию для этого системного статуса. delivered заполняет delivered_at и ставит custom_status в dostavlen («Доставлен»).

    Чтобы назначить пользовательский статус, передайте его permalink в custom_status_permalink. InSales также установит связанный с ним системный статус. Если передать в этом поле системный код (new, accepted, approved и другие из списка выше), он будет записан как fulfillment_status.

    Если одновременно передать несовместимые fulfillment_status и custom_status_permalink, API вернёт 422:

    {"message": "incompatible fulfillment and custom statuses"}

    Неизвестное значение fulfillment_status отклоняется со статусом 422 и сообщением «имеет непредусмотренное значение».

    Параметр version содержит время updated_at в целых секундах. Если заказ изменился позже переданного version, API вернёт 409 с телом {}.

    История изменений возвращается в order_changes. У каждой записи есть action, value_was, value_is, created_at, full_description и user_name. Для запроса приложения user_name содержит название ключа доступа. При смене системного статуса action равен fulfillment_status_changed.

    Промокод, группа и бонусы в заказе

    Чтобы применить промокод при создании заказа, передайте его в coupon. Регистр не учитывается: DOCSAPI10 и docsapi10 обозначают один код. Скидка возвращается в discounts, а поле discount дублирует первую скидку.

    Для строки стоимостью 100 код на 10% даёт итог 90, код на 50 рублей — итог 50. Повторное использование кода с act_once: true отклоняется со статусом 422: «Указан несуществующий купон, убедитесь, что он введен верно».

    Задачи пользователя

    Список задач можно прочитать, если у приложения есть право читать заказы. Создавать и менять задачу можно, если есть право изменять информацию заказа.

    GET /admin/user_tasks.json возвращает массив задач без общего количества записей. У задачи есть id, complete, order_id, assignee_id, title, description, created_at, updated_at, deadline_at и order. Если задача связана с заказом, order содержит объект {id, number}; иначе в списке возвращается null. Данные автора в JSON не включаются.

    assignee_id — идентификатор пользователя магазина. У запроса приложения assignee=me выбирает задачи с пустым assignee_id.

    Создание задачи возвращает 200. Если deadline_at не передан, срок устанавливается на один час позже времени создания.

    Если complete не передан, поле сохраняется как null. Явно переданное false сохраняется как false. Фильтр complete=false не включает задачи с null. Для фильтрации используйте строки true или false: значение complete=1 не включает фильтр. Если одновременно переданы completed и complete, применяется completed.

    API сохраняет order_id и assignee_id, даже если соответствующего заказа или пользователя нет. Для несуществующего заказа объект order отсутствует в ответе создания, а в списке равен null.

    title обязателен, длиннее 1000 символов отвечает 422, тело {"title":["слишком большой длины (не может быть больше чем 1000 символов)"]}. Пустой title при изменении отвечает 422, тело {"title":["Не заполнены обязательные поля"]}.

    Промокоды

    GET /admin/discount_codes.json возвращает промокоды по убыванию идентификаторов. Параметр q ищет подстроку в коде и описании: например, q=docs возвращает записи с этой подстрокой. Для чтения изменений поддерживаются updated_since и from_id.

    Новый код по умолчанию выключен: disabled равен true, worked равен false, act_once равен true, type_id равен 2. Код приводится к нижнему регистру: DOCSAPI10 сохраняется как docsapi10. Повтор того же кода отвечает 422, тело {"code":["уже существует"]}.

    type_id 1 — процент, 2 — сумма. Процент больше либо равный 100 не проходит проверку. min_price — минимальная сумма товаров. Код применяется, если сумма не ниже порога.

    Чтобы промокод можно было применить к заказу, передайте disabled: false при создании или обновлении. Запрос PUT возвращает {"status":"ok"}; обновлённую карточку получите отдельным GET. Запрос DELETE также возвращает {"status":"ok"}.

    collection_ids ограничивает код коллекциями. В ответе появляется discount_collections с collection_id. discount_collections_group_id связывает код с группой коллекций. В самом коде этого id нет: связь видна в GET /admin/discount_collections_groups/:id/discount_codes.json.

    Поле worked равно false, если код выключен или одноразовый код уже использован. После применения к заказу кода с act_once: true его worked становится false. Создать второй заказ с тем же купоном нельзя.

    Группы скидок на коллекции

    GET /admin/discount_collections_groups.json и GET /admin/discount_collections_groups/:id.json возвращают группы, которые заведены в бэк-офисе. У группы есть id, title, collection_ids и collections с id, title, parent_id, permalink. Создать или изменить группу этим API нельзя: POST /admin/discount_collections_groups.json отвечает 404.
