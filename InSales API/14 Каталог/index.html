    Каталог

    Товар, привязка товара к коллекции, свойства вариантов и типы цен описаны в товарах. Каналы продаж приложения — в приложениях. Отзывы бэк-офиса — в отзывах. Склады и валюты склада — в складах. Здесь — справочники и методы вокруг товара: коллекции витрины, категории учёта, фильтры и дополнительные поля.

    Тело без корневого объекта отвечает 422, в message назван ожидаемый ключ, например collection. Несуществующий id в GET отвечает 404 с HTML-страницей.

    Коллекции

    Коллекция — раздел витрины. Корневая коллекция магазина приходит с пустым parent_id. Скрытая коллекция (is_hidden: true) в список входит. Коллекция, помеченная к удалению, из списка пропадает.

    У обычной коллекции is_smart в ответе равен null. Ключ image есть только у коллекции с картинкой.

    Список

    GET /admin/collections.json без page и per_page отдаёт весь список. Порядок — parent_id, затем position: коллекция без родителя стоит в конце.

    parent_id оставляет дочерние коллекции этого родителя. parent_id=null оставляет коллекции без родителя.

    page или per_page включают постраничную выдачу. per_page меньше 10 поднимается до 10, больше 250 опускается до 250. В заголовке ответа есть X-TOTAL-PAGES. page меньше 1 отвечает 422.

    GET/admin/collections.json?per_page=10&page=1
    Параметр Описание
    per_page необязательный
    число    		 Размер страницы. Меньше 10 поднимается до 10, больше 250 опускается до 250.
    page необязательный
    число    		 Номер страницы, начиная с 1.
    parent_id необязательный
    число    		 Только дочерние коллекции. null — коллекции без родителя.
    updated_since необязательный
    строка    		 Нижняя граница updated_at, граница входит в ответ.

Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json

    {"message":"page должен иметь значение, большее 0"}

    Изменившиеся коллекции

    updated_since оставляет коллекции с updated_at больше или равным переданному времени. Порядок такого ответа — updated_at, затем id. Время передают в query целиком, двоеточие и знак часового пояса кодируют.

    Параметр from_id список коллекций не меняет: набор и порядок те же, что в запросе без него. Следующую пачку сдвигают новым updated_since. Одна и та же граница может прийти снова, потому что запись с этим временем входит в ответ.

    Строка, которую нельзя разобрать как дату, фильтр не включает. Ответ приходит целиком, порядок у него уже по updated_at и id.

    GET/admin/collections.json?updated_since=2026-10-21T22%3A00%3A00%2B03%3A00
    Параметр Описание
    updated_since обязательный
    строка    		 Момент изменения. Коллекция с этим updated_at входит в ответ. 
    GET /admin/collections.json?updated_since=2026-10-21T22%3A00%3A00%2B03%3A00
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json

    Ответ · 200

    [
  {
    "id": 53486015,
    "updated_at": "2026-10-21T22:14:15.000+03:00",
    "title": "docs-api Витрина"
  },
  {
    "id": 53486016,
    "updated_at": "2026-10-21T22:14:15.000+03:00",
    "title": "docs-api dup"
  }
]

    У записи списка есть id, updated_at и title.

    Создание и изменение

    POST /admin/collections.json создаёт коллекцию и отвечает 201. parent_id обязателен. Занятый permalink запрос не отклоняет: к нему дописывается суффикс -2.

    sort_type — код порядка товаров в коллекции. Чужой код отвечает 422, в ошибке sort_type со значением «имеет непредусмотренное значение».

    Код Порядок
    1 По алфавиту: А — Я
    2 По алфавиту: Я — А
    3 По дате: новые — старые
    4 По дате: старые — новые
    5 По цене: дорогие — дешёвые
    6 По цене: дешёвые — дорогие
    7 Ручная
    8 По скидке: большая — маленькая
    9 По скидке: маленькая — большая
    10 По весовому коэффициенту: маленький — большой
    11 По весовому коэффициенту: большой — маленький
    12 Сначала непопулярные
    13 Сначала популярные

    recursive: true сохраняется в ответе. description принимает HTML. Значения дополнительных полей пишутся массивом field_values_attributes и возвращаются в field_values.

    Картинка

    Картинка передаётся публичным адресом в image_attributes.src при создании и при PUT уже существующей коллекции. Пока файл обрабатывается, original_url равен /images/loading.gif.

    POST/admin/collections.json
    Параметр Описание
    collection[title] обязательный
    строка    		 Название коллекции.
    collection[parent_id] обязательный
    число    		 id родительской коллекции.
    collection[image_attributes][src] обязательный
    строка    		 Публичный адрес файла картинки. 
    POST /admin/collections.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "collection": {
    "title": "docs-api Картинка",
    "parent_id": 53486010,
    "image_attributes": {
      "src": "https://upload.wikimedia.org/wikipedia/commons/c/ca/1x1.png"
    }
  }
}

    Ответ · 201

    {
  "id": 53486017,
  "title": "docs-api Картинка",
  "permalink": "docs-api-kartinka",
  "image": {
    "id": 1,
    "created_at": "2026-10-21T22:14:16.000+03:00",
    "original_url": "/images/loading.gif"
  }
}

    Тот же объект image_attributes в PUT /admin/collections/:id.json отвечает 200 и тоже отдаёт original_url равным /images/loading.gif, пока файл обрабатывается.

    Умная коллекция

    Умная коллекция собирает товары по фильтрам. POST с is_smart: true и пустым списком фильтров отвечает 422:

    {"smart_collection_filters":["Настройте хотя бы один фильтр"]}

    POST, в котором умная коллекция и фильтры приходят вместе, отвечает 500 и коллекцию не создаёт. Рабочий порядок — сначала обычная коллекция, затем PUT с is_smart и smart_collection_filters_attributes. Ответ 200, is_smart равен true. Сами фильтры в JSON коллекции не возвращаются.

    method_or_field_name задаёт поле и ключ через двоеточие. Для названия это title:. values — массив.

    Поле Операторы
    title: contain, not_contain
    price: between
    discount: greater_than
    created_at: greater_than, less_than, greater_than_or_equal, less_than_or_equal, older_than, younger_than
    property:ID in, empty, notempty

    Для свойства в method_or_field_name после двоеточия стоит id свойства. У empty и notempty список values может быть пустым. Запрос ниже оставляет коллекции, в названии которых есть строка.

    Состав умной коллекции пересчитывается после сохранения. products_count может ещё не содержать эту коллекцию.

    PUT/admin/collections/53486018.json
    Параметр Описание
    id обязательный
    число    		 id уже созданной коллекции.
    collection[is_smart] обязательный
    логический    		 Включить умную коллекцию.
    collection[smart_collection_filters_attributes] обязательный
    массив    		 Фильтры: method_or_field_name, operator, values. 
    PUT /admin/collections/53486018.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "collection": {
    "is_smart": true,
    "smart_collection_filters_attributes": [
      {
        "method_or_field_name": "title:",
        "operator": "contain",
        "values": ["Gallery"]
      }
    ]
  }
}

    Ответ · 200

    {
  "id": 53486018,
  "parent_id": 53486010,
  "is_hidden": false,
  "is_smart": true,
  "sort_type": 7,
  "title": "docs-api page 0",
  "permalink": "docs-api-page-0",
  "url": "/collection/docs-api-page-0",
  "field_values": []
}

    Удаление

    DELETE /admin/collections/:id.json у дочерней коллекции отвечает 200 и {"status":"ok"}. Следующий GET этой коллекции — 404 с HTML-страницей.

    Тот же DELETE у корневой коллекции тоже отвечает {"status":"ok"}, и коллекция остаётся на месте.

    DELETE/admin/collections/53486025.json
    Параметр Описание
    id обязательный
    число    		 id дочерней коллекции. 
    DELETE /admin/collections/53486025.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json

    Ответ · 200

    {"status":"ok"}

    Ответ · 200

  },
  {
    "id": 53486014,
    "count": 5
  }
]

    Категории

    Категория — раздел учёта товара. В карточке товара это category_id. Коллекция витрины в это поле не подставляется.

    GET /admin/categories.json отдаёт все категории без постраничной нарезки. Порядок и отбор updated_since и parent_id такие же, как у коллекций: from_id список не меняет. В объекте только id, parent_id, title, position, created_at, updated_at.

    POST /admin/categories.json отвечает 201. Меняются title, parent_id и position.

    category[parent_id] необязательный
    число    		 id родительской категории.
    category[position] необязательный
    число    		 Позиция среди соседей. 
    POST /admin/categories.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "category": {
    "title": "docs-api Учёт",
    "parent_id": 1,
    "position": 5

    {
  "id": 9,
  "parent_id": 1,
  "title": "docs-api Учёт",
  "position": 5,
  "created_at": "2026-10-21T22:14:20.000+03:00",
  "updated_at": "2026-10-21T22:14:20.000+03:00"
}

    Перенос товаров

    PUT /admin/categories/set_products_category.json переносит перечисленные товары в категорию. Ответ {"status":"ok"}. В карточке товара category_id становится равным new_category_id.

    PUT/admin/categories/set_products_category.json
    Параметр Описание
    new_category_id обязательный
    число    		 id категории, в которую переносятся товары.
    product_ids обязательный
    массив    		 id товаров. 
    PUT /admin/categories/set_products_category.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "new_category_id": 9,
  "product_ids": [673]
}

    Ответ · 200

    {"status":"ok"}

    Удаление

    DELETE /admin/categories/:id.json у дочерней категории отвечает {"status":"ok"}, затем GET этой категории — 404. Товары этой категории уходят в архив.

    DELETE корневой категории тоже отвечает {"status":"ok"}, и категория остаётся.

    PUT /admin/categories/recover.json товары из архива не возвращает и отвечает ошибкой сервера.

    Фильтры коллекций

    Фильтр коллекции — SEO-страница внутри коллекции: название, адрес и набор параметров товара и свойств варианта. Методы доступны, когда фильтры коллекций есть в тарифе.

    Список GET /admin/collection_filters.json постраничный. per_page меньше 10 поднимается до 10, больше 500 опускается до 500, без параметра страница содержит до 500 записей. Заголовка X-TOTAL-PAGES нет. collection_id оставляет фильтры одной коллекции; с ним порядок по position, без него — по коллекции и позиции.

    Тело создания и изменения лежит в ключе filter. Ответ 201 на создание и 200 на изменение. Характеристики в ответе лежат в поле characteristis — так ключ называется в JSON. Значения дополнительных полей в этот JSON не входят.

    properties_attributes и options_attributes ищут параметр и свойство по названию и создают отсутствующие. Повтор того же набора параметров и свойств в той же коллекции отвечает 422:

    {"properties_attributes":["Уже существует фильтр с такими параметрами и свойствами"]}

    Название фильтра уникально внутри коллекции.

    Дополнительные поля коллекции

    Поле коллекции создаётся с типом CollectionField::TextField или CollectionField::TextArea. Другой type отвечает 500, поле не создаётся.

    POST /admin/collection_fields.json отвечает 201. В ответе есть application_id и application_title приложения, от имени которого создано поле. Повтор handle отвечает 422:

    {"handle":["Свойство с таким пермалинком уже существует"]}

    GET /admin/collection_fields/:id.json читает поле по числовому id. Если в сегменте пути есть не только цифры, поле ищется по handle.

    POST/admin/collection_fields.json
    Параметр Описание

    строка    		 Системное имя. Уникально в магазине.
    collection_field[type] обязательный
    строка    		 CollectionField::TextField или CollectionField::TextArea.
    collection_field[position] необязательный
    число    		 Позиция поля.
    collection_field[is_hidden] необязательный
    логический    		 Скрыть поле.

    Значение поля

    Значение можно передать при сохранении коллекции через field_values_attributes. Отдельные методы: список, чтение и изменение. Создания и удаления отдельным методом нет.

    GET /admin/collections/:collection_id/collection_field_values.json — значения этой коллекции. GET и PUT одного значения идут по id поля или по его handle.

    Если значения ещё нет, GET отвечает 200 и объект с пустыми id и value, запись при этом не создаётся. PUT создаёт или меняет значение и отвечает {"status":"ok"}. Новое значение читается следующим GET.

Authorization: Basic API_KEY:API_PASSWORD

    Значения дополнительных полей

    Поля товара и варианта и запись значения вместе с товаром разобраны в товарах. Ниже те же значения отдельными методами. Пустой массив в карточке значит, что значений нет.

    Товар

    GET /admin/products/:product_id/product_field_values.json — значения товара. POST создаёт значение и отвечает 201. Повтор того же поля отвечает 422:

    {"product_field_id":["уже существует"]}

    В создании можно передать product_field_id или product_field_handle. Чтение, изменение и удаление идут по id значения или по handle поля.

    PUT отвечает объектом значения. DELETE отвечает {"status":"ok"}, следующий список этого товара — [].

    product_field_value[value] обязательный
    строка    		 Значение.

    Значения варианта лежат на пути /admin/variants/:variant_id/variant_field_values.json. Путь /admin/products/:product_id/variants/:variant_id/variant_field_values.json отвечает 404.
