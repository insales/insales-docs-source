    Выгрузки товаров

    Выгрузки можно читать и менять, если у приложения есть право на маркетплейсы.

    Если этого права нет, ответ 403:

    {"status":"error","message":"Недостаточно прав для операции"}

    Выгрузки товаров

    Ресурс /admin/marketplaces позволяет создавать файлы выгрузок товаров для внешних площадок. Идентификатор id в пути должен быть числом. Запрос с текстовым идентификатором, например GET /admin/marketplaces/abc.json, возвращает страницу 404 витрины.

    Поле url содержит публичный адрес файла, доступный без HTTP Basic. XML-файл возвращается с Content-Type: application/xml; charset=utf-8. Ссылки внутри него используют хост, с которого запрошен файл.

    Если язык из lang не включён в магазине, возвращается тот же файл. При формировании файла на лету параметр download=1 не добавляет заголовок скачивания.

    GET /admin/marketplaces.json возвращает массив выгрузок. Набор полей зависит от type. При создании в ответе 201 поле collection_ids может содержать [], даже если идентификаторы сохранены. Проверьте их следующим GET-запросом.

    В файл попадают товары выбранных коллекций. Пустой список коллекций и пустая коллекция дают файл без товаров. Архивный товар из файла пропадает. Товар вне выбранных коллекций в файл не входит.

    Чтобы создать выгрузку другого типа, используйте отдельный POST. Если изменить type существующей записи через PATCH, API вернёт HTML-страницу 404, хотя тип записи уже изменится.

    DELETE /admin/marketplaces/ID.json отвечает 200, тело {"status":"ok"}.

    Какие типы создаются одним названием

    Для создания передайте name и type. Неизвестное значение type отклоняется со статусом 422 и телом {"type":["Тип является обязательным полем"]}. Если передать только name, без type, API вернёт 500 с HTML-страницей.

    Название должно быть непустым и уникальным в магазине. При повторе возвращается 422 и {"name":["Выгрузка с таким названием уже существует"]}, при пустом названии — 422 и {"name":["Не указано название выгрузки"]}. Дополнительные обязательные поля зависят от типа:

    type Ответ на name и type
    Marketplace::GoogleMerchant 201, файл .xml
    Marketplace::ExcelPrices 201, url заканчивается на .xls
    Marketplace::LiquidYandexMarket 201, в ответе шаблон offer_liquid по умолчанию
    Marketplace::ModelYandexMarket 422: пустые shop_name, shop_company, vendor_id
    Marketplace::YandexMarket 422: пустые shop_name, shop_company
    Marketplace::Sbermegamarket 422: пустые shop_name, shop_company
    Marketplace::CartsLiquidYandexMarket 422: touched_carts_days_ago должен быть от 0 до 30
    Marketplace::Avito 422: пустые address и category_id, плюс непринятые listing_fee, ad_status, condition_type

    Google Merchant

    Достаточно названия и типа. description_type принимает 1 и 2. adult, utm_label, local_delivery_cost и collection_ids сохраняются и возвращаются. Отрицательная стоимость доставки отвечает 422, тело {"local_delivery_cost":["Стоимость доставки должна быть неотрицательным числом, например 300"]}.

    brand принимается и влияет на файл, в JSON записи его нет. not_load_not_available, show_hidden и layout_template в JSON тоже не возвращаются.

    POST/admin/marketplaces.json
    Параметр Описание
    name обязательный
    строка    		 Название выгрузки, уникальное в магазине.
    type обязательный
    строка    		 Marketplace::GoogleMerchant. 
    POST /admin/marketplaces.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "marketplace": {
    "name": "docs-min-GoogleMerchant",
    "type": "Marketplace::GoogleMerchant"
  }
}

  "id": 1,
  "name": "docs-min-GoogleMerchant",
  "type": "Marketplace::GoogleMerchant",
  "created_at": "2026-10-21T22:22:44.698+03:00",
  "updated_at": "2026-10-21T22:22:44.698+03:00",
  "url": "https://demo.myinsales.ru/marketplace/1.xml",

    Яндекс.Маркет, модель

    Длина shop_name не должна превышать 20 символов. Более длинное значение отклоняется со статусом 422 и телом {"shop_name":["Название магазина не может быть длиннее 20 символов."]}. Поле vendor_id содержит идентификатор параметра товара. Для несуществующего идентификатора API возвращает 422 и {"vendor_id":["Такого параметра для указания производителя не существует"]}.

    При создании collection_ids возвращается пустым массивом, хотя категории уже включены в файл. Следующий PUT возвращает список коллекций, даже если не передавать их повторно. В стандартном файле модельной выгрузки дата указана во времени магазина, со смещением часового пояса.

    type обязательный
    строка    		 Marketplace::ModelYandexMarket.
    shop_name обязательный
    строка    		 Название магазина в файле, до 20 символов.
    shop_company обязательный
    строка    		 Название компании в файле.
    vendor_id обязательный
    число    		 Идентификатор параметра, из которого берётся производитель.
    collection_ids необязательный
    массив    		 Коллекции товаров. В ответе 201 массив может быть пустым.

    число    		 Стоимость доставки в файле.

    строка    		 Примечание к условиям продажи.

    Произвольный шаблон

    Если при создании Marketplace::LiquidYandexMarket не передать offer_liquid, API вернёт 201 и сохранит стандартный шаблон товарного предложения (оффера). В нём используются product.id, product.price, product.title, product.properties.vendor, account.url и collection.id.

    Шаблон с ошибкой Liquid отклоняется со статусом 422, например: {"offer_liquid":["Offer liquid содержит ошибку: Liquid syntax error (line 1): 'if' tag was never closed"]}.

    В шаблоне оффера доступны product, account и collection: product.id, product.title, product.price, product.cost_price, product.sku, product.currency_id, product.available, product.variants.first.id, product.variants.first.cost_price, account.url, collection.id, collection.title. Закупочная цена выводится и как product.cost_price, и как product.variants.first.cost_price, когда она заполнена у варианта.

    К параметру товара можно обратиться по permalink или названию: product.properties.brand и product.properties['Бренд']. Значение product.properties.vendor будет пустым, пока в магазине нет параметра с таким именем. Чтобы использовать параметр в шаблоне, выберите его в настройках выгрузки. В API выбор передаётся объектом с числовыми ключами.

    PATCH/admin/marketplaces/49.json
    Параметр Описание
    offer_liquid необязательный
    строка    		 Шаблон одного оффера. Ошибка синтаксиса отвечает 422.
    marketplace_properties_attributes необязательный
    объект    		 Ключи 0, 1, … и property_id выбранных параметров.
    use_variants необязательный
    логический    		 Включает данные вариантов в шаблоне.
    collection_ids необязательный
    массив    		 Коллекции, чьи товары попадают в файл. 
    PATCH /admin/marketplaces/49.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "marketplace": {
    "use_variants": true,
    "collection_ids": [53486010],
    "marketplace_properties_attributes": {
      "0": {
        "property_id": 61541199
      }
    },
    "offer_liquid": "<offer id=\"{{ product.id }}\">\n  <name>{{ product.title }}</name>\n  <price>{{ product.price }}</price>\n  <cost>{{ product.cost_price }}</cost>\n  <sku>{{ product.sku }}</sku>\n  <brand>{{ product.properties.brand }}</brand>\n</offer>"
  }
}

    Ответ · 200

    {
  "id": 49,
  "name": "docs-lym",
  "type": "Marketplace::LiquidYandexMarket",
  "use_variants": true,
  "collection_ids": [53486010],
  "offer_liquid": "<offer id=\"{{ product.id }}\">…</offer>",
  "shop_name": "Docs Liquid",
  "shop_company": "Docs Co",
  "url": "https://demo.myinsales.ru/marketplace/49.xml"
}

    offer_liquid в JSON сокращён. Выбранного параметра в JSON нет, он виден в файле.

    Параметр Описание
    id обязательный
    число    		 Идентификатор выгрузки в пути. 
    GET /marketplace/49.xml
Accept: application/xml

    Ответ · 200

    <offer id="673">
  <name>docs-api catalog product</name>
  <price>10.0</price>

    Вокруг оффера стандартная обёртка yml_catalog: категории, валюта RUB, пустой блок акций.

    Для получения значения выбранного дополнительного поля используйте product.fields.HANDLE. Оно возвращается строкой, без обращения к .value. Если поле не выбрано, подстановка пустая. Поле marketplace_product_fields_attributes не принимается: запрос возвращает 422:

    {
  "marketplace_product_fields.account_id": ["Не заполнены обязательные поля"],
  "marketplace_product_fields.product_field": ["Не заполнены обязательные поля"]
}

    Шаблон offer_liquid описывает одно товарное предложение. Цикл {% for product in products %} не перебирает товары в этом шаблоне.

    Общий шаблон файла задаётся через layout_template. В нём доступны content_for_layout (уже сформированные предложения), marketplace.shop_name, marketplace.company, account.url и currency. Переменной products нет. Поле layout_template не возвращается в JSON записи, но используется при формировании файла.

    Фильтр {{ 'now' | date: '%Y-%m-%d %H:%M' }} выводит время UTC. Например, в файле магазина с часовым поясом +03:00 он может вывести 2026-10-21 19:36 по UTC. В стандартном шаблоне модельной выгрузки Яндекса дата остаётся во времени магазина.

    PATCH/admin/marketplaces/49.json
    Параметр Описание
    layout_template обязательный
    строка    		 Обёртка файла. Офферы подставляются в content_for_layout. 
    PATCH /admin/marketplaces/49.json
Authorization: Basic API_KEY:API_PASSWORD
Accept: application/json
Content-Type: application/json

{
  "marketplace": {
    "layout_template": "<yml_catalog date=\"{{ 'now' | date: '%Y-%m-%d %H:%M' }}\">\n<shop>\n<name>{{ marketplace.shop_name }}</name>\n<company>{{ marketplace.company }}</company>\n<url>{{ account.url }}</url>\n<currency>{{ currency }}</currency>\n<offers>{{ content_for_layout }}</offers>\n<has_products>{% if products %}yes{% else %}no{% endif %}</has_products>\n</shop>\n</yml_catalog>"
  }
}

    Ответ · 200

    {
  "id": 49,
  "type": "Marketplace::LiquidYandexMarket",
  "shop_name": "Docs Liquid",
  "shop_company": "Docs Co",
  "url": "https://demo.myinsales.ru/marketplace/49.xml"
}

    В JSON нет layout_template. Файл собирается по сохранённой обёртке. currency в ней равен RUR.

    GET/marketplace/49.xml
    Параметр Описание
    id обязательный
    число    		 Идентификатор выгрузки в пути. 
    GET /marketplace/49.xml
Accept: application/xml

    Ответ · 200

    <yml_catalog date="2026-10-21 19:36">
  <shop>
    <name>Docs Liquid</name>
    <company>Docs Co</company>
    <url>https://demo.myinsales.ru</url>
    <currency>RUR</currency>
    <offers>
      <offer id="673">
        <name>docs-api catalog product</name>
        <price>10.0</price>
      </offer>
    </offers>
    <has_products>no</has_products>
  </shop>
</yml_catalog>

    Дата в файле — UTC. Оффер в файле равен текущему offer_liquid.
