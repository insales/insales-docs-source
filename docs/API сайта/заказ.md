# Заказ

Быстрый заказ забирает текущую корзину браузера. Перед запросом в корзине должен лежать хотя бы один товар. Обязательны телефон, способ доставки, способ оплаты и все поля, которые магазин пометил обязательными в оформлении заказа.

Id доставки и оплаты шаблон берёт из `account.delivery_variants` и `account.payment_gateways`. Способ оплаты должен быть разрешён для выбранной доставки, доставка должна быть доступна в регионе покупателя.

## Успешный заказ

Согласие на обработку персональных данных передаётся полем `client[consent_to_personal_data]` со значением `1`, если магазин сделал это поле обязательным.

## Ошибка проверки

Тот же запрос без согласия:

```json
{
  "status": "unprocessable_entity",
  "errors": {
    "client.consent_to_personal_data": [
      "Не заполнено обязательное поле \"Согласие на обработку персональных данных\""
    ]
  },
  "client_errors": {
    "consent_to_personal_data": [
      "Не заполнено обязательное поле \"Согласие на обработку персональных данных\""
    ]
  },
  "shipping_address_errors": {}
}
```

`errors` — сводка по заказу. `client_errors` и `shipping_address_errors` разбирают поля покупателя и адреса. Набор обязательных полей у каждого магазина свой: имя, телефон и согласие в этом примере не универсальный список.

Собственные поля оформления заказа передаются их id, шаблонизатор их не печатает.

## Заказ в один клик

`POST /quick_checkout.json` создаёт заказ из формы «в один клик», не из основной корзины. Общий вид тела — поля `client[...]` и состав `variants`. На магазине, где форма не настроена, этот адрес отвечает страницей ошибки, а не JSON. Подключайте его только там, где в бэк-офисе есть форма быстрого заказа.

Альтернативный адрес той же операции в темах — `POST /orders/create_with_quick_checkout.json`.
