# Как интегрироваться с InSales

Через API бэк-офиса приложение может создавать, читать, изменять и удалять объекты магазина: товары, заказы, клиентов и остальные ресурсы из [справочника InSales API](https://api.insales.ru/).

Отправляйте запросы на адрес магазина, который InSales передаёт в параметре `shop` при установке приложения. Путь к ресурсу начинается с `/admin/`. Суффикс `.json` или `.xml` задаёт формат данных.

```
GET https://SHOP/admin/account.json
```

Для авторизации используйте HTTP Basic: логин — идентификатор приложения, пароль — пароль приложения в конкретном магазине. Для каждого магазина используется свой пароль.

`GET`, `HEAD` и `DELETE` не требуют заголовка `Content-Type`. Для `POST`, `PUT` и `PATCH` он обязателен и должен соответствовать суффиксу адреса: `application/json` для `.json`, `application/xml` для `.xml`. Если тип содержимого не соответствует формату, API возвращает статус `422` и тело `{"message":"incorrect Content-Type, should be application/json"}` либо такое же сообщение для `application/xml`.

Вопросы по приложениям: [partners@insales.ru](mailto:partners@insales.ru).

## Лимит запросов

Лимит для одного приложения в одном магазине — 500 запросов за 5 минут. Пятиминутный интервал начинается с первого запроса серии. Запросы с неверным паролем тоже учитываются. Текущее значение счётчика возвращается в заголовке `API-Usage-Limit`, например `API-Usage-Limit: 1/500`.

Если лимит превышен, API возвращает `429 Too Many Requests` с пустым телом. Заголовок `Retry-After` содержит число секунд до конца текущего интервала: по нему можно определить, когда повторить запрос.

## Коды ответов

* `200` — операция выполнена.
* `201` — объект создан.
* `400` — API не смог разобрать тело запроса, например из-за невалидного JSON в запросе к `.json`.
* `401` — ошибка авторизации HTTP Basic.
* `403` — у приложения нет права на операцию. Тело: `{"status":"error","message":"..."}`.
* `404` — объект не найден.
* `422` — неверный `Content-Type` или поля не прошли проверку.
* `429` — исчерпан лимит, см. `Retry-After`.

## Установка приложения

Создайте приложение в партнёрском кабинете. Укажите идентификатор приложения (логин для HTTP Basic), секрет и URL обработчика установки без параметров, например `https://myapp.example/install`.

Когда пользователь нажимает «Установить», InSales создаёт одноразовый `token` и вычисляет пароль приложения для этого магазина:

```
password = MD5(token + secret)
```

В обработчике установки вычислите пароль по той же формуле: соедините `token` и секрет приложения без разделителя и получите MD5 в шестнадцатеричном виде, в нижнем регистре. Сохраните пароль в приложении: InSales не отправляет `token` повторно.

InSales вызывает обработчик установки GET-запросом:

```
https://myapp.example/install?shop=SHOP&token=TOKEN&insales_id=INSALES_ID
```

* `shop` — адрес магазина, на него дальше уходят запросы API.
* `insales_id` — постоянный идентификатор магазина.
* `token` — одноразовая строка для расчёта пароля.

К моменту вызова обработчика пароль уже действует. Поэтому во время установки можно обращаться к API, например создавать [вебхуки](07%20InSales%20API%20-%20Webhooks.md).

Обработчик установки должен вернуть HTTP-статус `200` в течение 10 секунд. Если он вернёт другой статус или не ответит за это время, InSales отменит установку. Пароль приложения в этом магазине перестанет действовать.

## Вход пользователя в приложение

Кнопка входа открывает URL входа из настроек приложения и добавляет параметры:

```
https://myapp.example/login?shop=SHOP&insales_id=INSALES_ID&user_id=USER_ID&user_email=USER_EMAIL
```

Если у пользователя ещё нет сессии в приложении, перенаправьте его браузер на адрес автологина магазина:

```
https://SHOP/admin/applications/API_KEY/login?token=TOKEN&login=https://myapp.example/autologin
```

`API_KEY` — идентификатор приложения. Для `token` приложение создаёт новую строку; токен установки здесь не используется. В `login` укажите адрес обработчика автологина приложения. Его домен должен совпадать с доменом URL входа из настроек: InSales проверяет домен второго уровня.

Если пользователь вошёл в бэк-офис и приложение установлено в магазине, InSales перенаправляет браузер на адрес из `login` со следующими параметрами:

* `token` — `MD5(token + password)`
* `user_email`, `user_name`, `user_id`
* `token2` — `MD5(token + user_email + user_name + user_id + password)`
* `email_confirmed` — `true` или `false`
* `token3` — `MD5(token + user_email + user_name + user_id + email_confirmed + password)`

В формулах используйте исходный `token`, который приложение передало в запросе автологина. `password` — сохранённый пароль приложения в этом магазине. Сравнение рассчитанного значения с полученным `token3` позволяет проверить, что переход выполнен из бэк-офиса.

## Удаление приложения

При удалении приложения InSales вызывает URL обработчика удаления GET-запросом:

```
UNINSTALL_URL?shop=SHOP&token=PASSWORD&insales_id=INSALES_ID
```

В этом запросе параметр `token` содержит пароль приложения в магазине. Секрет приложения и токен установки здесь не используются.
