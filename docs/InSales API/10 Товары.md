# Товары

Через API можно создавать товары, управлять их вариантами, ценами и остатками, добавлять изображения и дополнительные поля. В этой статье также описаны привязка товаров к коллекциям, опции покупки и комплекты.

## Список

`GET /admin/products.json` возвращает массив товаров. Чтобы узнать количество товаров с теми же фильтрами, используйте `GET /admin/products/count.json`.

Параметр `per_page` задаёт количество товаров на странице. Если передать значение меньше 10, API использует 10. Номер страницы задаётся параметром `page`.

## Создание

Для создания товара достаточно передать название и один вариант с ценой. InSales формирует адрес товара (`permalink`) из названия. Описание сохраняется в виде переданного HTML.

Поле `category_id` задаёт категорию учёта. Если его не передать, магазин выберет категорию автоматически. Идентификатор коллекции витрины для этого поля не подходит: API вернёт `422` и `{"category_id":["Категория удалена или отсутствует."]}`. Чтобы добавить товар в коллекцию, используйте отдельный запрос из следующего раздела.

Если отправить запрос на запись без `Content-Type: application/json`, API вернёт `422`:

```json
{"message": "incorrect Content-Type, should be application/json"}
```

<a id="удаление-и-архив"></a>

## Удаление и архив

`DELETE /admin/products/:id.json` переносит товар в архив и возвращает `{"status":"ok"}`. После этого чтение карточки без архивных флагов возвращает `404` с HTML-страницей.

Если товара с указанным идентификатором нет, `DELETE` также возвращает `200` и `{"status":"ok"}`. По ответу на удаление нельзя определить, существовал ли товар.

По умолчанию список не содержит архивных товаров. С `deleted=true` API возвращает только архивные товары с `archived: true`. С `with_deleted=true` возвращаются и текущие, и архивные товары. Ниже показана одна запись из списка с `deleted=true`.

<a id="параметры"></a>

## Параметры

Параметр описывает товар целиком, например его материал, состав или длину. В API параметр представлен свойством `property` и его значением `characteristic`. При создании или обновлении товара передайте название свойства и его значение в `properties_attributes`.

Размер и цвет, от которых зависят варианты товара, задаются [свойствами вариантов](#варианты). Гравировка или подарочная упаковка могут быть [опциями покупки](#опция-покупки): у каждого значения такой опции есть своя цена.

Чтобы прочитать параметры товара, запросите `GET /admin/products/:id.json`. Массив `properties` содержит свойства, а `characteristics` — их значения. Поле `property_id` у значения указывает на `id` свойства. Название значения хранится в `title`.

### Запись по названиям

Если свойства или значения с переданным названием ещё нет в магазине, API создаёт его. Несколько элементов `properties_attributes` с одинаковым `title` задают несколько значений одного свойства. В ответе будет одно свойство и несколько значений с одинаковым `property_id`.

### Числовой параметр

## Свойства вариантов {#свойства-вариантов}

Свойство варианта — справочник значений, например размеров или цветов. Чтобы назначить свойство товару, передайте `title` и `value` в `product.options`, как описано в разделе [«Варианты»](#варианты). Поле `option_name_id` внутри `variants_attributes` в этом запросе не принимается.

`GET /admin/option_names.json` возвращает свойства без вложенных значений. Поле `api_permalink` состоит из префикса `o-` и значения `permalink`. Параметр `sorting_type` принимает `manual` или `auto`, но в ответе не возвращается.

## Варианты {#варианты}

Вариант — это сочетание значений свойств вроде размера и цвета, со своей ценой, остатком, артикулом и штрихкодом. Справочник свойств (`option_name`) — в [свойствах вариантов](#свойства-вариантов). Параметр карточки (`property`) из раздела «Параметры» — другой справочник. Цена и остаток меняются у варианта, отдельного поля цены у товара в этих запросах нет.

У товара всегда остаётся хотя бы один вариант.

### Внешний идентификатор

`external_id` — идентификатор варианта во внешней системе. Его пишут в уже созданный вариант запросом `PUT /admin/products/:product_id/variants/:id.json`.

При создании товара данные вариантов передаются в `variants_attributes`: цена, артикул, остаток, вес и габариты. Поле `external_id` в этом вложенном объекте не поддерживается. Если передать его при создании товара, API вернёт `422` и укажет недопустимый ключ:

```json
{"variants_attributes": ["undefined keys [\"external_id\"]"]}
```

Обновление варианта с `"external_id": "1c-200"` возвращает `200`. Значение сохраняется у варианта, но не включается в его JSON-ответ.

### Остаток {#остаток}

`quantity` — остаток варианта. Остаток на складе передаётся полем `quantity_at_warehouseN`. Число `N` — это `array_index` склада из `GET /admin/warehouses.json`. У единственного склада индекс `0`, поле называется `quantity_at_warehouse0`.

Если в магазине один склад, `quantity` и `quantity_at_warehouse0` описывают один остаток: изменение любого из этих полей меняет оба. Остаток склада возвращается строкой, например `"7.0"`. Работа с несколькими складами и суммарным остатком описана в разделе [«Склады»](18%20Склады.md#склады).

### Групповое обновление

`PUT /admin/products/variants_group_update.json` меняет цены и остатки сразу у нескольких вариантов. В теле — массив `variants`, у каждого элемента обязателен `id`:

```json
{"variants": [{"id": 2176487279, "price": 1900}]}
```

API сразу возвращает `200` с пустым массивом `[]`. Изменения применяются не сразу. Чтобы проверить новые цены и остатки, повторно запросите варианты после завершения обновления.

## Типы цен {#типы-цен}

Тип цены позволяет хранить у варианта дополнительную цену. Методы доступны, если эта возможность входит в тариф магазина. На обычном тарифе можно создать не более 20 типов цен.

`POST /admin/price_kinds.json` отвечает `201`. `price_index` начинается с 1. `variant_price_method_name` для первого типа — `price2`: в варианте это поле `price2`. Следующий тип получает следующий индекс и поле `price3`. Повтор названия отвечает `422`:

```json
{"title":["уже существует"]}
```

`PUT /admin/price_kinds/:id.json` меняет `title` и `show_in_lists`.

## Единицы измерения {#единицы-измерения}
Список можно прочитать, если у приложения есть право на настройки магазина.

## Изображения

Чтобы добавить изображение к товару, используйте `POST /admin/products/:product_id/images.json`. Пока InSales обрабатывает файл, `image_processing` равен `true`, а URL изображений указывают на `/images/loading.gif`. Имя файла в ответе уже соответствует загруженному файлу.

### Адрес изображения

`src` — публичный адрес файла. Магазин скачивает изображение по этому адресу, поэтому адрес должен открываться из интернета. Если файл по адресу скачать нельзя, ответ `422`:

```json
{"image": ["Не заполнены обязательные поля"], "src": ["Недопустимый URL"]}
```

## Комплект

Чтобы создать комплект, передайте при создании товара `"bundle": true` и состав в `product_bundle_components_attributes`. Для каждой составляющей укажите `variant_id` другого товара и количество. Цену комплекта задайте в его собственном варианте через `variants_attributes`.

Признак `bundle` можно задать только при создании товара. Если обновить обычный товар, передав `"bundle": true` и состав комплекта, API вернёт `200`, но товар не станет комплектом. В ответе `bundle` будет равен `null`, а `product_bundle_components` — пустому массиву.
