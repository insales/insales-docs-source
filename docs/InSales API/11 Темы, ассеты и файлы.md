# Темы, ассеты и файлы

Темы, ассеты и типы виджетов можно читать и менять, если у приложения есть право на дизайн. Для файлов раздела «Контент — Файлы» нужно право на файлы. Для панелей блоков — право на блоки.

Если нужного права нет, ответ `403`:

```json
{"status":"error","message":"Недостаточно прав для операции"}
```

Новую тему через этот API создать нельзя: `POST /admin/themes.json` отвечает `404`. Скачать тему архивом нельзя: `GET /admin/themes/:id/export.json` отвечает `404`.

На витрине файл темы и файл раздела «Контент — Файлы» — разные адреса. Файл темы попадает в шаблон через фильтр `asset_url`, файл раздела — через `file_url`.

## Ассеты темы

Ассет — файл внутри темы: шаблон, сниппет, картинка, стиль, скрипт или JSON из каталога `config`. Адрес: `/admin/themes/:theme_id/assets.json`.

`type` при создании:

| Тип | Что это | Имя в запросе |
| --- | --- | --- |
| `Asset::Template` | Шаблон страницы. К имени дописывается `.liquid`. | `product.docs_api` становится `product.docs_api.liquid` |
| `Asset::Snippet` | Сниппет. К имени дописывается `.liquid`. | `docs_api_note` становится `docs_api_note.liquid` |
| `Asset::Media` | Картинка, CSS, JS и прочие файлы в корне темы. | Имя как есть, с расширением: `docs-api.png` |
| `Asset::Configuration` | JSON настроек в `config`. | `docs-api.json`, `settings_data.json` |

Список отдаёт id, тип, имя, человекочитаемое имя, адрес и `version` (unix-время изменения). Содержимого в списке нет.

## Создание ассета

Повтор с тем же именем — `422`:

```json
{"inner_file_name":["Файл с именем docs_api_note.liquid уже существует"]}
```

```json
{"inner":["Ошибка синтаксиса: Liquid syntax error (line 1): [:end_of_string] is not a valid expression in \"\""]}
```

CSS и JSON создаются тем же полем `content`. Для CSS тип — `Asset::Media`, для JSON — `Asset::Configuration`. `raw.json` возвращает текст файла как есть.

## Виджеты темы

Публичное API работает с типами виджетов темы: `/admin/themes/:theme_id/widget_types.json`. Список содержит только свои типы этой темы. Системных виджетов в нём нет. Поставить виджет на страницу, прочитать список виджетов страницы или панели `header` / `content` / `footer` этим API нельзя: `GET /admin/themes/1/widgets.json`, `GET /admin/widget_lists.json` и `GET /admin/widgets.json` отвечают `404`.

Виджет в карточке заказа или товара бэк-офиса — другой ресурс, [виджеты приложения](05%20InSales%20API%20-%20Widgets.md).

Поля создания лежат в корне JSON. Объект внутри ключа `widget_type` отвечает `422`: ключ назван неизвестным, обязательные поля — пропущенными.

`page_kinds` — массив из `all`, `index`, `collection`, `product`, `cart`, `page`, `search`, `blog`, `article`, `compare`, `favorite`, `shared_cart`. Чужое значение даёт `422`: `{"page_kinds":{"0":["is not valid"]}}`.

`widget_list_kinds` — массив из `header`, `before_content`, `content`, `sidebar`, `after_content`, `footer`, `outside`, `top_panel`, `bottom_panel`. Чужое значение: `{"widget_list_kinds":{"0":["is not valid"]}}`.

`widget_category_handle` — handle существующей категории, например `benefits`. Неизвестная категория: `422`, `widget_category_id` — «Не заполнены обязательные поля».

`PUT` меняет переданные поля и возвращает тип целиком. `GET /admin/themes/:theme_id/widget_types.json` возвращает массив таких объектов. `GET` одного id — один объект. `DELETE` отвечает `200` и пустым телом, следующий `GET` — HTML `404`.

`POST /admin/block_lists.json` с `name` и `liquid_name` отвечает `404`. Страница содержит «Couldn't find BlockList without an ID». `PUT` панели в JSON отвечает `406`. Панель через JSON этим методом не меняется.

Списка блоков нет: `GET /admin/blocks.json` отвечает `404`. `POST /admin/blocks.json` с названием и текстом отвечает `200` и `{"status":"error","errors":{}}`. Тот же запрос в XML отвечает `422` с пустым `<errors/>`. Отдельного чтения одного блока нет.

Состав блоков поколения 4, который виден в редакторе темы, в эту пару методов не входит. Его читают как файл `setup.json` темы через `raw.json`. Разместить виджет на панели публичным API нельзя.
