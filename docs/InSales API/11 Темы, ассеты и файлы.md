# Темы, ассеты и файлы

Для чтения и изменения тем, ассетов и типов виджетов приложению нужно право на дизайн. Для работы с разделом «Контент — Файлы» нужно право на файлы, для панелей блоков — право на блоки.

Если нужного права нет, ответ `403`:

```json
{"status":"error","message":"Недостаточно прав для операции"}
```

Новую тему через этот API создать нельзя: `POST /admin/themes.json` отвечает `404`. Скачать тему архивом нельзя: `GET /admin/themes/:id/export.json` отвечает `404`.

Файлы темы и файлы раздела «Контент — Файлы» имеют разные адреса на витрине. В шаблоне используйте фильтр `asset_url` для файла темы и `file_url` для файла из раздела «Контент — Файлы».

## Ассеты темы

Ассет — файл внутри темы: шаблон, сниппет, картинка, стиль, скрипт или JSON из каталога `config`. Адрес: `/admin/themes/:theme_id/assets.json`.

`type` при создании:

| Тип | Что это | Имя в запросе |
| --- | --- | --- |
| `Asset::Template` | Шаблон страницы. К имени дописывается `.liquid`. | `product.docs_api` становится `product.docs_api.liquid` |
| `Asset::Snippet` | Сниппет. К имени дописывается `.liquid`. | `docs_api_note` становится `docs_api_note.liquid` |
| `Asset::Media` | Картинка, CSS, JS и прочие файлы в корне темы. | Имя как есть, с расширением: `docs-api.png` |
| `Asset::Configuration` | JSON настроек в `config`. | `docs-api.json`, `settings_data.json` |

Список возвращает идентификатор, тип, имя, человекочитаемое имя, адрес и `version` — время изменения в формате Unix. Содержимое файлов в список не включается.

## Создание ассета

Для создания ассета отправьте `POST /admin/themes/:theme_id/assets.json`. Заголовок `Content-Type: application/json` обязателен. Без него API вернёт `422` и `{"message":"incorrect Content-Type, should be application/json"}`.

Чтобы создать сниппет, передайте его текст в `content`. InSales автоматически добавит расширение `.liquid` к имени.

Повтор с тем же именем — `422`:

```json
{"inner_file_name":["Файл с именем docs_api_note.liquid уже существует"]}
```

```json
{"inner":["Ошибка синтаксиса: Liquid syntax error (line 1): [:end_of_string] is not a valid expression in \"\""]}
```

## Виджеты темы

Для работы с типами виджетов темы используйте `/admin/themes/:theme_id/widget_types.json`. Список возвращает только собственные типы указанной темы; системные типы не включаются.

Размещать виджеты на странице, получать список виджетов страницы и панели `header` / `content` / `footer` через этот API нельзя. Запросы `GET /admin/themes/1/widgets.json`, `GET /admin/widget_lists.json` и `GET /admin/widgets.json` возвращают `404`.

Виджет в карточке заказа или товара бэк-офиса — другой ресурс, [виджеты приложения](05%20InSales%20API%20-%20Widgets.md).

При создании типа виджета передавайте поля на верхнем уровне JSON. Если вложить их в `widget_type`, API вернёт `422`: ключ будет отмечен как неизвестный, а обязательные поля — как пропущенные.

`page_kinds` — массив из `all`, `index`, `collection`, `product`, `cart`, `page`, `search`, `blog`, `article`, `compare`, `favorite`, `shared_cart`. Чужое значение даёт `422`: `{"page_kinds":{"0":["is not valid"]}}`.

`widget_list_kinds` — массив из `header`, `before_content`, `content`, `sidebar`, `after_content`, `footer`, `outside`, `top_panel`, `bottom_panel`. Чужое значение: `{"widget_list_kinds":{"0":["is not valid"]}}`.

`widget_category_handle` — handle существующей категории, например `benefits`. Неизвестная категория: `422`, `widget_category_id` — «Не заполнены обязательные поля».

Пустой JSON `{}` на создание отвечает `422` и перечисляет пропущенные поля: `type`, `name`, `handle`, `snippet_content`, `generation`, `page_kinds`, `widget_list_kinds`. Неизвестный `type` — `{"type":["is not valid"]}`.

`PUT` меняет переданные поля и возвращает тип целиком. `GET /admin/themes/:theme_id/widget_types.json` возвращает массив таких объектов. `GET` одного id — один объект. `DELETE` отвечает `200` и пустым телом, следующий `GET` — HTML `404`.

Виджет со списком блоков создаётся типом `BlockListWidgetType`. В `block_template_handle` передаётся handle системного шаблона блока, например `system-benefit`. В ответе это поле возвращается вместе с остальными полями простого виджета.

Создать панель через `POST /admin/block_lists.json` с `name` и `liquid_name` нельзя: API возвращает `404` со страницей «Couldn't find BlockList without an ID». Изменение панели через `PUT` в JSON возвращает `406`; панель не изменяется.

Получить список блоков через `GET /admin/blocks.json` нельзя: API возвращает `404`. Запрос `POST /admin/blocks.json` с названием и текстом возвращает `200` и `{"status":"error","errors":{}}`. В формате XML тот же запрос возвращает `422` с пустым `<errors/>`. Отдельного метода чтения блока нет.

Для чтения состава блоков поколения 4, который отображается в редакторе темы, получите файл `setup.json` через `raw.json`. Методы панелей блоков не возвращают этот состав. Разместить виджет на панели через публичный API нельзя.
