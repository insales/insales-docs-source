# Магазин

Аккаунт и домены можно читать и менять, если у приложения есть право на настройки магазина.

Действия приложения описаны в [приложениях](14%20Приложения,%20выгрузки,%20задачи%20и%20диалоги.md#действия-приложения). Доставка и точки самовывоза описаны в [доставке](17%20Доставка.md). Единицы измерения товара — в [товарах](10%20Товары.md#единицы-измерения). Склады и валюты склада — в [складах](18%20Склады.md). Способы оплаты — в [оплате](19%20Способы%20оплаты.md).

Если нужного права нет, ответ `403`:

```json
{"status":"error","message":"Недостаточно прав для операции"}
```

Дополнительные поля заказа, клиента и адреса — в [заказах и клиентах](12%20Заказы%20и%20клиенты.md#дополнительное-поле).

## Аккаунт

`GET /admin/account.json` отдаёт один объект магазина. Отдельного списка нет: аккаунт у приложения один.

В том же объекте есть флаги скидок `enable_cart_discounts`, `enable_client_discounts`, `enable_group_discounts`, `enable_order_discounts`, а также `hide_items_out_of_stock`, `contact_phone`, `sms_notification_phone`, `icq`, `registration_type_id`, `inviter_id`, `created_at`.

`stock_currency_exchange_rate` — курс валюты склада по умолчанию к валюте сайта. При одинаковой валюте курс равен `1.0`. Как задать валюту — в [складах](18%20Склады.md#валюты-склада).

`PUT /admin/account.json` сохраняет два поля: `next_order_number` и `client_cookies_whitelist`. Название, организация, город и остальные ключи из ответа остаются прежними. Успех и ошибка полей приходят с HTTP `200`. Успех — `{"status":"ok"}`.

`next_order_number` — номер, который получит следующий заказ. Новое значение больше наибольшего номера уже существующего заказа. `client_cookies_whitelist` — список cookie, которые заказ сохраняет при оформлении. Это регулярные выражения, каждое с новой строки.

## Домены

`GET /admin/domains.json` отдаёт домены магазина, основной первым. Технический поддомен `*.insales.io` в этот список не входит. Пустой магазин отвечает `[]`.

Создание снимает схему, путь и префикс `www.`. `https://www.docs-api-shop.example/path` сохраняется как `docs-api-shop.example`. Поддомен третьего уровня сохраняется целиком: `msk.docs-api-shop.example`.

<tr><td><code>domain[main]</code> <span class="api-opt">необязательный</span><br>логический</td><td>Признак основного домена. При создании можно не передавать.</td></tr>

```json
  "main": false,
  "created_at": "2026-10-21T22:21:32.000+03:00",
  "updated_at": "2026-10-21T22:21:32.000+03:00"
}
```

</div>
</div>
</div>

Первый домен сам по себе основным не становится. `PUT /admin/domains/4310871.json` с `{"domain":{"main":true}}` отвечает `200` и `"main": true`. Пока домен не настроен, `main_host` аккаунта остаётся техническим адресом.

Повтор того же имени — `422`, тело `{"domain":["Вы уже добавили этот домен"]}`. Имя без точки — `422`, тело `{"domain":["Неверный формат имени домена","Неверный формат имени домена"]}`: сообщение приходит дважды. Имя с `insales.ru` — `422`, тело `{"domain":["Домен не должен содержать в себе слова insales или ekam"]}`.

`GET /admin/domains/:id/verify.json` отдаёт ключ проверки домена обычным текстом, заголовок `Content-Type: text/plain`. В JSON домена этого ключа нет.
