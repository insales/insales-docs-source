# Каталог

Здесь описаны коллекции витрины, категории учёта, фильтры коллекций и дополнительные поля. Создание товаров, привязка к коллекциям, свойства вариантов и типы цен описаны в разделе [«Товары»](10%20Товары.md).

Связанные ресурсы: [каналы продаж приложения](14%20Приложения,%20выгрузки,%20задачи%20и%20диалоги.md#каналы-продаж), [отзывы](16%20Отзывы.md), [склады и валюты склада](18%20Склады.md).

Если передать тело без ожидаемого корневого объекта, API вернёт `422`. Поле `message` укажет, какой ключ нужен, например `collection`. Чтение объекта с несуществующим идентификатором возвращает `404` с HTML-страницей.

## Коллекции

Коллекция — раздел витрины. Корневая коллекция магазина приходит с пустым `parent_id`. Скрытая коллекция (`is_hidden: true`) в список входит. Коллекция, помеченная к удалению, из списка пропадает.

У обычной коллекции `is_smart` в ответе равен `null`. Ключ `image` есть только у коллекции с картинкой.

### Список

`GET /admin/collections.json` без `page` и `per_page` возвращает все коллекции. Они сортируются по `parent_id`, затем по `position`. Коллекция без родителя находится в конце списка.

Для чтения дочерних коллекций передайте `parent_id` родительской коллекции. Значение `parent_id=null` возвращает коллекции без родителя.

Чтобы получать список по страницам, передайте `page` или `per_page`. Размер страницы ограничен диапазоном от 10 до 250: API заменяет значения за его пределами ближайшей границей. Количество страниц возвращается в заголовке `X-TOTAL-PAGES`. Если `page` меньше 1, API вернёт `422`.

### Изменившиеся коллекции

Параметр `updated_since` возвращает коллекции, у которых `updated_at` больше либо равен указанному времени. Результат сортируется по `updated_at`, затем по `id`. Передавайте время целиком в параметре URL, кодируя двоеточия и знак смещения часового пояса.

Параметр `from_id` не меняет состав и порядок списка коллекций. Для следующего запроса изменяйте `updated_since`. Записи с граничным временем могут вернуться повторно, поскольку сравнение включает указанное время.

Если значение `updated_since` не удаётся разобрать как дату, фильтрация по времени не применяется. API возвращает список без этого ограничения, но сортирует его по `updated_at` и `id`.

### Создание и изменение

`POST /admin/collections.json` создаёт коллекцию и возвращает статус `201`. Поле `parent_id` обязательно. Если `permalink` уже занят, InSales добавляет суффикс `-2`, не отклоняя запрос.

`sort_type` — код порядка товаров в коллекции. Чужой код отвечает `422`, в ошибке `sort_type` со значением «имеет непредусмотренное значение».

| Код | Порядок |
| --- | --- |
| 1 | По алфавиту: А — Я |
| 2 | По алфавиту: Я — А |
| 3 | По дате: новые — старые |
| 4 | По дате: старые — новые |
| 5 | По цене: дорогие — дешёвые |
| 6 | По цене: дешёвые — дорогие |
| 7 | Ручная |
| 8 | По скидке: большая — маленькая |
| 9 | По скидке: маленькая — большая |
| 10 | По весовому коэффициенту: маленький — большой |
| 11 | По весовому коэффициенту: большой — маленький |
| 12 | Сначала непопулярные |
| 13 | Сначала популярные |

`recursive: true` сохраняется в ответе. `description` принимает HTML. Значения дополнительных полей пишутся массивом `field_values_attributes` и возвращаются в `field_values`.

`PUT /admin/collections/:id.json` меняет те же поля и отвечает `200` объектом коллекции.

### Умная коллекция

Умная коллекция собирает товары по фильтрам. `POST` с `is_smart: true` и пустым списком фильтров отвечает `422`:

```json
{"smart_collection_filters":["Настройте хотя бы один фильтр"]}
```

Создавайте умную коллекцию в два шага:

1. Создайте обычную коллекцию.
2. Отправьте `PUT` с `is_smart` и `smart_collection_filters_attributes`.

API вернёт `200` и `is_smart: true`. Фильтры в JSON коллекции не включаются. Если попытаться сразу создать умную коллекцию с фильтрами через `POST`, API вернёт `500` и не создаст коллекцию.

`method_or_field_name` задаёт поле и ключ через двоеточие. Для названия это `title:`. `values` — массив.

| Поле | Операторы |
| --- | --- |
| `title:` | `contain`, `not_contain` |
| `price:` | `between` |
| `discount:` | `greater_than` |
| `created_at:` | `greater_than`, `less_than`, `greater_than_or_equal`, `less_than_or_equal`, `older_than`, `younger_than` |
| `property:ID` | `in`, `empty`, `notempty` |

Для фильтра по свойству укажите его идентификатор после двоеточия в `method_or_field_name`. С операторами `empty` и `notempty` массив `values` может быть пустым. В примере ниже фильтр выбирает товары по подстроке в названии.

Состав умной коллекции пересчитывается после сохранения.

## Категории

Категория задаёт раздел учёта товара и указывается в его поле `category_id`. Идентификатор коллекции витрины в этом поле использовать нельзя.

`GET /admin/categories.json` возвращает все категории без постраничного деления. Сортировка и фильтрация по `updated_since` и `parent_id` работают так же, как у коллекций. Параметр `from_id` не меняет список. Объект категории содержит только `id`, `parent_id`, `title`, `position`, `created_at` и `updated_at`.

`POST /admin/categories.json` отвечает `201`. Меняются `title`, `parent_id` и `position`.

### Удаление

При удалении дочерней категории `DELETE /admin/categories/:id.json` возвращает `{"status":"ok"}`. Следующее чтение категории возвращает `404`. Товары, находившиеся в этой категории, переносятся в архив.

`DELETE` корневой категории тоже отвечает `{"status":"ok"}`, и категория остаётся.

## Фильтры коллекций

Фильтр коллекции — SEO-страница внутри коллекции с собственным названием, адресом и набором параметров товара и свойств варианта. Методы доступны, если фильтры коллекций входят в тариф магазина.

`GET /admin/collection_filters.json` возвращает список по страницам. По умолчанию на странице до 500 записей. Параметр `per_page` ограничен диапазоном от 10 до 500; значения за пределами диапазона заменяются ближайшей границей. Заголовка `X-TOTAL-PAGES` нет.

Чтобы получить фильтры одной коллекции, передайте `collection_id`. С ним список сортируется по `position`, без него — по коллекции и позиции.

При создании и изменении передавайте данные в корневом объекте `filter`. При создании API возвращает `201`, при изменении — `200`. В ответе характеристики находятся в поле `characteristis`: сохраняйте именно такое написание ключа. Значения дополнительных полей в ответ не включаются.

`properties_attributes` и `options_attributes` ищут параметр и свойство по названию и создают отсутствующие. Повтор того же набора параметров и свойств в той же коллекции отвечает `422`:

```json
{"properties_attributes":["Уже существует фильтр с такими параметрами и свойствами"]}
```

Название фильтра уникально внутри коллекции.

## Дополнительные поля коллекции

Для дополнительного поля коллекции используйте тип `CollectionField::TextField` или `CollectionField::TextArea`. Другие значения `type` приводят к ответу `500`, поле при этом не создаётся.

`POST /admin/collection_fields.json` отвечает `201`. В ответе есть `application_id` и `application_title` приложения, от имени которого создано поле. Повтор `handle` отвечает `422`:

```json
{"handle":["Свойство с таким пермалинком уже существует"]}
```

`GET /admin/collection_fields/:id.json` читает поле по числовому id. Если в сегменте пути есть не только цифры, поле ищется по `handle`.

## Значения дополнительных полей

Создание дополнительных полей товара и варианта, а также запись значений вместе с товаром описаны в разделе [«Товары»](10%20Товары.md#дополнительное-поле-товара). Ниже показана работа со значениями через отдельные методы. Пустой массив в карточке означает, что значений нет.

### Товар

`GET /admin/products/:product_id/product_field_values.json` — значения товара. `POST` создаёт значение и отвечает `201`. Повтор того же поля отвечает `422`:

```json
{"product_field_id":["уже существует"]}
```

`PUT` отвечает объектом значения. `DELETE` отвечает `{"status":"ok"}`, следующий список этого товара — `[]`.
