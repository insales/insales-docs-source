# Витрина

Блоги, статьи, страницы, меню, JS-теги и редиректы.

Отсутствующий id отвечает `404` и HTML, не JSON. Так ведут себя блог, статья, страница, меню, пункт меню, JS-тег и редирект.

`PUT` меняет запись. `PATCH` у блога и страницы вызывает то же изменение и возвращает тот же статус. У редиректа `PUT` и `PATCH` отвечают `404`: у этого ресурса нет метода изменения.

`page` меньше 1 и `page` от 1000000 отвечают `422`:

```json
{"message": "page должен иметь значение, большее 0"}
```

Пустое тело там, где метод ждёт объект, отвечает `422` и `param is missing or the value is empty or invalid` с именем `blog`, `menu`, `js_tag` или `redirect`.

Запись создаётся своим `POST`, удаляется своим `DELETE`.

## Язык

Текстовые поля блога и статьи читаются и пишутся на языке параметра `lang`. Язык должен быть включён в магазине. `GET` без `lang` возвращает язык магазина по умолчанию.

Один `POST` создаёт одну запись. Второй `POST` с другим `lang` создаёт вторую запись, а не перевод. Перевод той же записи — `PUT` на её id с другим `lang`. `permalink` при этом не меняется. `title`, `content` и `author` записываются на языке `lang`. `GET` с тем же `lang` возвращает текст этого языка.

Если языка в магазине нет, значение из `?lang=` записывается в язык по умолчанию и меняет текст этого языка.

## Блоги

`GET /admin/blogs.json` отдаёт все блоги одним массивом, без страниц. Адрес блога, который не является главным, — `/blogs/{handle}`. Поле в JSON называется `handle`, отдельного `permalink` у блога нет.

`commentable` на витрине использует `no`, `yes` и `moderable`. Другое значение тоже сохраняется и возвращается.

`category` принимает значение из списка: Авто, Военторг, Дизайн, Дом, Еда, Здоровье, Знаменитости, Игры, Кино, Культура, Литература, Мода, Музыка, Наука, Общество, Политика, Природа, Происшествия, Психология, Путешествия, Спорт, Технологии, Фотографии, Хобби, Экономика, Юмор. Чужое значение отвечает `422`. `category`, `check_spam_enabled` и `custom_layout` в JSON блога нет: запрос с ними проходит, повторное чтение эти поля не возвращает. `custom_template` в ответе есть. Имя файла шаблона в теме — в [темах, ассетах и файлах](11%20Темы,%20ассеты%20и%20файлы.md).

## Статьи

Создание идёт внутрь блога: `POST /admin/blogs/:blog_id/articles.json`.

`GET /admin/blogs/:blog_id/articles.json` — статьи одного блога. Порядок: закреплённая, затем `published_at` по убыванию, затем id по убыванию.

На странице по умолчанию 10 статей. `per_page` и `limit` меньше 10 поднимаются до 10, сверху значение обрезается до 250. `updated_since` список не фильтрует.

Обязательны `title`, `content`, `author` и `published_at`. Пустые поля отвечают `422`, и ключ текста — `content_with_urls`, не `content`. Дата без времени сохраняется как полночь в часовом поясе магазина: `2024-05-02` стал `2024-05-02T00:00:00.000+03:00`.

`permalink` можно задать. Если его нет, он строится из названия транслитом.

Адрес опубликованной статьи — `/blogs/{handle}/{permalink}`, ответ витрины `200`. Статья с `published_at` в будущем в API есть, этот адрес на витрине отвечает `404`, а `/blogs/{handle}/{permalink}/preview` — `200`. Адрес `/blog/{permalink}` у блога, который не главный, отвечает `404`.

Комментариев статьи в этом API нет. `GET /admin/comments.json` и `GET /admin/blogs/:blog_id/articles/:id/comments.json` отвечают `404`.

### Создание статьи

`all_tags` заменяет весь список тегов. Тегов может быть 30. 31 тег отвечает `422`: «Невозможно задать больше 30 тегов к статье.»

Товары задаются `related_products_attributes` с `product_id`. Массив id в `related_products` создаёт статью с пустым списком товаров. Неизвестный id отвечает `422`: «Товары 999999999 не найдены». Снять товар — тот же массив с `_destroy: true`.

`related_products` — товары статьи.

Закреплённой остаётся одна статья. Вторая с `pinned: true` снимает закрепление с предыдущей: у первой в следующем чтении `pinned` стал `false`.

HTML в `content` сохраняется как передан, включая `meta` и `script`.

## Страницы

Адрес страницы — `/page/{permalink}`. `GET /admin/pages.json` отдаёт страницы без фиксированного порядка.

По умолчанию и при `per_page` меньше 25 на странице 25 записей. Сверху значение обрезается до 1000.

`content` обязателен. `permalink` можно задать. Занятый permalink сохраняется с суффиксом `-2`. Занятое название отвечает `422`: «уже существует». `created_at` можно передать, значение сохраняется. `custom_template` сохраняется и возвращается. Файл шаблона — в [темах](11%20Темы,%20ассеты%20и%20файлы.md).

`is_hidden` и `kind` из запроса не применяются. В ответе `is_hidden` равен `false`, `kind` — `only_page`.

Если меню уже есть, новая страница становится пунктом первого меню. `menu_id` в запросе меню не выбирает. Пункт получает название страницы и адрес `/page/{permalink}`.

## Пункты меню

`GET /admin/menus/:menu_id/items.json` отдаёт плоский список. Поля родителя нет, вложенность этим ресурсом не задаётся. Позиции при создании идут с 1 по порядку.

`related_object_id` связывает пункт с объектом. Адрес в `url` для страницы, категории и блога собирается сам.

| `related_object_id` | `url` в ответе |
| --- | --- |
| `Page_31` | `/page/docs-api-page` |
| `Collection_53486010` | `/collection/all` |
| `Blog_9` | `/blogs/docs-api-blog` |
| `Page_0` | адрес из `url` |
| `Page_-2` | `/cart_items` |
| `Page_-3` | `/client_account/login` |
| `Page_-5` | `/compares` |
| `Page_-6` | `/favorites` |
| `Page_-7` | якорь из `url`, сохраняется `#delivery` |

Внешняя ссылка без `related_object_id` сохраняется как `Page_0`. Произвольный путь тоже: `Page_0` и `url` `/page/docs-api-page`.

Название уникально внутри меню. Пустое название и неверный адрес отвечают `422`, ошибки лежат в объекте `errors`. У блога и страницы объект `errors` в таком ответе не используется.

Свободная `position`, например 50, сохраняется. Занятая позиция в `PUT` отвечает `200` и в теле показывает переданное число, а следующий `GET` оставляет прежнюю позицию.

Удаление пункта отвечает `200` с пустым телом.

## JS-теги

JS-тег вставляет код на витрину. Список `GET /admin/js_tags.json` содержит только теги приложения, чей ключ стоит в Basic. Другой ключ получает пустой массив, а `GET` и `DELETE` чужого id отвечают `404`.

Текст тега — JavaScript, не Liquid. Скобки Liquid остаются текстом и на витрине не исполняются. Код попадает на витрину у тега с `enabled: true`. Поле `enabled` принимается и хранится, в JSON его нет.

Для скрипта в карточке заказа или товара бэк-офиса есть [виджеты приложения](05%20InSales%20API%20-%20Widgets.md).

Тип — `JsTag::TextTag` или `JsTag::FileTag`. `PUT` может сменить тип. В тексте `TextTag` нельзя писать тег `script`: ответ `422`, «В теле не должно быть тега &lt;script&gt;». У `FileTag` в `content` лежит URL файла. Неадрес отвечает `422` с ключом `url`, не `content`. Неизвестный тип не записывает поля и отвечает `422` сразу по `content`, `account_id` и `type`.

## Редиректы

`POST /admin/redirects.json` создаёт редирект. Изменить его нельзя: `PUT` и `PATCH` отвечают `404`. Удаляется по одному, `DELETE` отвечает `{"status":"ok"}`. Общего удаления нет.

Витрина отвечает `301` на адрес, который находится по правилам ниже. Редирект действует на запрос страницы. Адрес с суффиксом `.json` витрина по этим правилам не перенаправляет.

Список по умолчанию содержит до 100 записей. Нижней границы у `per_page` нет. Порядок не задан: одна и та же запись может прийти и на первой, и на второй странице. Надёжнее поднять `per_page` или собирать id без повторов.

`q[q]` ищет подстроку в старом и новом адресе. `q[c_from]` и `q[c_to]` ограничивают `created_at` по часовому поясу магазина.

### Создание

Старый адрес сохраняется путём: схема и хост отбрасываются. `https://example.com/from-outside` сохраняется как `/from-outside`. Хвост `/` срезается. Запрос витрины на адрес с хвостом `/` с такой записью не совпадает.

Новый адрес на домене магазина тоже сохраняется путём, хвост `/` срезается: `https://abc.myinsales.ru/catalog/` сохраняется как `/catalog`. Новый адрес чужого сайта остаётся абсолютным: `https://example.com/catalog`.

Одинаковые старый и новый адреса отвечают `422`, ключ `new_url`: «имеет неверное значение».

Корень `/` и первый сегмент из списка ниже создавать нельзя. Текст для `/delivery`: «Недопустимый URL. Путь '/delivery/' не может быть использован в качестве первой составной части старого URL.» Для корня в том же тексте путь `///`.

Запрещённый первый сегмент: `orders`, `cart_items`, `payments`, `auth`, `address`, `delivery`, `payment`, `fast_checkout`, `new_order`, `compares`, `cities`, `bank_receipts`, `yandex_market`, `yandex_snippets`, `torg_mail`, `sitemap`, `robots`, `juridical_person_receipts`, `yandex_market_fast_checkout`, `counter_settings`, `codes_settings`.

### Цепочки

Новый старый адрес не может совпадать с новым адресом уже существующего редиректа, и новый адрес не может совпадать со старым адресом другого. Ответ `422`.

«Уже существует редирект на адрес ...» — ключ `old_url`. «Уже существует редирект с адреса ...» — ключ `new_url`.

`remove_redirect_chains` со значением `1` создаёт новую запись и переписывает новый адрес у тех редиректов, которые вели на этот старый адрес. Их id сохраняются.

### Как витрина выбирает адрес

Пока среди редиректов нет старого адреса с `?`, сравнивается путь, а query копируется на новый адрес. Правило, в чьём старом адресе есть `?`, в этом режиме не используется.

Первый `POST` такого правила в этом режиме может ответить `500` и не сохранить запись. Магазин при этом переключается на точное сравнение. Повторный такой же `POST` отвечает `201`.

Дальше путь и query должны совпасть. Параметры `domain` и `locale` отбрасываются. Параметры `_ga`, `tagtag_uid`, `erid`, `gsaid`, `advcake_params`, `utm_source`, `utm_medium`, `utm_campaign`, `yclid`, `ysclid`, `utm_referrer`, `utm_content` и `utm_term` на совпадение не влияют и дописываются к новому адресу. `page` к ним не относится: адрес с `page` и правило без query не совпадают.

`*` в конце старого адреса сравнивает этот путь целиком, с query и без него. Более длинный путь не совпадает. Это не регулярное выражение.

Лишние слэши в пути схлопываются и без записи: `/foo//bar` ведёт на `/foo/bar`.

В таблице цель цепочки — `/docs-api-final`. В колонке «точный режим» среди редиректов есть старый адрес с `?`. В колонке «только путь» таких редиректов нет.

| Запрос | Точный режим | Только путь |
| --- | --- | --- |
| `/docs-api-old` | `/docs-api-final` | `/docs-api-final` |
| `/docs-api-old?utm_source=ads` | `/docs-api-final?utm_source=ads` | `/docs-api-final?utm_source=ads` |
| `/docs-api-old?page=2` | совпадения нет | `/docs-api-final?page=2` |
| `/docs-api-q?color=red` | `/docs-api-final` | правило с `?` не используется |
| `/docs-api-q?color=blue` | совпадения нет | правило с `?` не используется |
| `/docs-api-q?utm_source=ads` | совпадения нет | правило с `?` не используется |
| `/docs-api-wild` и `/docs-api-wild?x=1` | `/docs-api-final` | `/docs-api-final`, query дописывается |
| `/docs-api-wild/extra` | совпадения нет | совпадения нет |
| `/page/docs-api-page?utm_source=ads&page=2` | совпадения нет | `/docs-api-final?utm_source=ads&page=2` |
