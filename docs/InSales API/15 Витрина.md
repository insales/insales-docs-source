# Витрина

Через API бэк-офиса приложение может управлять содержимым витрины: блогами, статьями, страницами, меню, JS-тегами и редиректами.

Если объекта с указанным идентификатором нет, API возвращает `404` с HTML-страницей, даже при запросе JSON. Это относится к блогам, статьям, страницам, меню, пунктам меню, JS-тегам и редиректам.

Для изменения записи используйте `PUT`. У блогов и страниц также поддерживается `PATCH`: он выполняет то же изменение и возвращает тот же статус. Редиректы нельзя изменить: для них `PUT` и `PATCH` возвращают `404`.

Если `page` меньше 1 или больше либо равен 1000000, API возвращает `422`:

```json
{"message": "page должен иметь значение, большее 0"}
```

Если метод ожидает корневой объект, а тело пустое, API возвращает `422` с сообщением `param is missing or the value is empty or invalid`. В сообщении указывается нужный ключ: `blog`, `menu`, `js_tag` или `redirect`.

Для создания записи используйте `POST` к соответствующему ресурсу, для удаления — `DELETE`.

## Язык

Параметр `lang` выбирает язык для чтения и записи текстовых полей блога и статьи. Язык должен быть включён в магазине. При чтении без `lang` возвращается текст на языке магазина по умолчанию.

Чтобы добавить перевод существующей записи, отправьте `PUT` на её идентификатор с нужным `lang`. Поля `title`, `content` и `author` сохранятся на указанном языке, а `permalink` останется прежним. Для чтения перевода передайте тот же `lang` в GET-запросе.

Каждый `POST` создаёт отдельную запись. Если повторить его с другим `lang`, появится вторая запись, а не перевод первой.

Если язык из `lang` не включён в магазине, текст сохраняется на языке по умолчанию, заменяя его текущее значение.

## Блоги

`GET /admin/blogs.json` возвращает все блоги одним массивом, без постраничного деления. Адрес блога, который не является главным, имеет вид `/blogs/{handle}`. В JSON используется поле `handle`; отдельного поля `permalink` у блога нет.

`commentable` на витрине использует `no`, `yes` и `moderable`. Другое значение тоже сохраняется и возвращается.

Поле `category` принимает одно из значений: Авто, Военторг, Дизайн, Дом, Еда, Здоровье, Знаменитости, Игры, Кино, Культура, Литература, Мода, Музыка, Наука, Общество, Политика, Природа, Происшествия, Психология, Путешествия, Спорт, Технологии, Фотографии, Хобби, Экономика, Юмор. Другие значения отклоняются со статусом `422`.

Поля `category`, `check_spam_enabled` и `custom_layout` принимаются в запросе, но не возвращаются в JSON блога, в том числе при повторном чтении. Поле `custom_template` возвращается. О назначении файла шаблона читайте в разделе [«Темы, ассеты и файлы»](11%20Темы,%20ассеты%20и%20файлы.md).

## Статьи

Чтобы создать статью, отправьте `POST /admin/blogs/:blog_id/articles.json` в нужный блог.

`GET /admin/blogs/:blog_id/articles.json` возвращает статьи одного блога. Сначала идёт закреплённая статья, затем остальные по убыванию `published_at` и `id`.

По умолчанию на странице 10 статей. Параметры `per_page` и `limit` ограничены диапазоном от 10 до 250: значения за его пределами заменяются ближайшей границей. Параметр `updated_since` не фильтрует список статей.

Для создания статьи обязательны `title`, `content`, `author` и `published_at`. Пустые значения отклоняются со статусом `422`. Ошибка текста возвращается под ключом `content_with_urls`, а не `content`.

Если дата публикации передана без времени, InSales использует полночь в часовом поясе магазина. Например, `2024-05-02` в магазине с поясом `+03:00` сохраняется как `2024-05-02T00:00:00.000+03:00`.

`permalink` можно задать. Если его нет, он строится из названия транслитом.

Опубликованная статья доступна на витрине по адресу `/blogs/{handle}/{permalink}` со статусом `200`. Если `published_at` находится в будущем, статья уже доступна в API, но её обычный адрес возвращает `404`. Предпросмотр `/blogs/{handle}/{permalink}/preview` возвращает `200`. Адрес `/blog/{permalink}` для статьи неглавного блога возвращает `404`.

Комментариев статьи в этом API нет. `GET /admin/comments.json` и `GET /admin/blogs/:blog_id/articles/:id/comments.json` отвечают `404`.

### Создание статьи

Поле `all_tags` заменяет список тегов целиком. Можно назначить не более 30 тегов. При передаче 31 тега API возвращает `422`: «Невозможно задать больше 30 тегов к статье.»

Чтобы привязать товары к статье, передайте `related_products_attributes` с `product_id`. Массив идентификаторов в `related_products` не привязывает товары: статья создаётся с пустым списком. Несуществующий идентификатор отклоняется со статусом `422`: «Товары 999999999 не найдены». Для удаления привязки передайте элемент того же массива с `_destroy: true`.

`related_products` — товары статьи.

Одновременно может быть закреплена одна статья. Если сохранить другую статью с `pinned: true`, у ранее закреплённой статьи `pinned` станет `false`.

HTML в `content` сохраняется как передан, включая `meta` и `script`.

## Страницы

Адрес страницы — `/page/{permalink}`. `GET /admin/pages.json` возвращает страницы без фиксированного порядка.

По умолчанию на странице до 25 записей. Если `per_page` меньше 25, API использует 25; если больше 1000 — 1000.

`content` обязателен. `permalink` можно задать. Занятый permalink сохраняется с суффиксом `-2`. Занятое название отвечает `422`: «уже существует». `created_at` можно передать, значение сохраняется. `custom_template` сохраняется и возвращается. Файл шаблона — в [темах](11%20Темы,%20ассеты%20и%20файлы.md).

`is_hidden` и `kind` из запроса не применяются. В ответе `is_hidden` равен `false`, `kind` — `only_page`.

Если в магазине уже есть меню, новая страница автоматически добавляется в первое из них. Параметр `menu_id` не позволяет выбрать другое меню. Пункт получает название страницы и адрес `/page/{permalink}`.

## Пункты меню

`GET /admin/menus/:menu_id/items.json` возвращает плоский список пунктов меню. Поля родителя нет, поэтому задать вложенность через этот ресурс нельзя. При создании пункты получают последовательные позиции, начиная с 1.

Поле `related_object_id` связывает пункт меню с объектом магазина. Для страницы, коллекции и блога InSales формирует `url` автоматически:

| `related_object_id` | `url` в ответе |
| --- | --- |
| `Page_31` | `/page/docs-api-page` |
| `Collection_53486010` | `/collection/all` |
| `Blog_9` | `/blogs/docs-api-blog` |
| `Page_0` | адрес из `url` |
| `Page_-2` | `/cart_items` |
| `Page_-3` | `/client_account/login` |
| `Page_-5` | `/compares` |
| `Page_-6` | `/favorites` |
| `Page_-7` | якорь из `url`, сохраняется `#delivery` |

Внешняя ссылка без `related_object_id` сохраняется как `Page_0`. Произвольный путь тоже: `Page_0` и `url` `/page/docs-api-page`.

Название уникально внутри меню. Пустое название и неверный адрес отвечают `422`, ошибки возвращаются в объекте `errors`. У блога и страницы объект `errors` в таком ответе не используется.

Свободное значение `position`, например 50, сохраняется. Если позиция занята, `PUT` возвращает `200` и переданное число в теле ответа, но фактическая позиция остаётся прежней. Проверяйте её отдельным GET-запросом.

Удаление пункта отвечает `200` с пустым телом.

## JS-теги

JS-тег позволяет добавить код на витрину. `GET /admin/js_tags.json` возвращает только теги приложения, указанного в авторизации HTTP Basic. Другой ключ получает пустой массив. Попытка прочитать или удалить чужой тег возвращает `404`.

В текст JS-тега передавайте JavaScript. Конструкции Liquid остаются текстом и не выполняются. Код подключается на витрине, если у тега `enabled: true`. Поле `enabled` принимается и сохраняется, но в JSON-ответ не включается.

Для скрипта в карточке заказа или товара бэк-офиса есть [виджеты приложения](05%20InSales%20API%20-%20Widgets.md).

JS-тег может иметь тип `JsTag::TextTag` или `JsTag::FileTag`. Тип можно изменить через `PUT`.

Для `TextTag` передавайте сам JavaScript без тега `script`. Если добавить тег, API вернёт `422`: «В теле не должно быть тега &lt;script&gt;». Для `FileTag` передавайте URL файла в `content`. Если значение не является адресом, ошибка `422` возвращается под ключом `url`, а не `content`. Неизвестный тип отклоняется со статусом `422` с ошибками по `content`, `account_id` и `type`; поля не сохраняются.

## Редиректы

Для создания редиректа используйте `POST /admin/redirects.json`. Изменение не поддерживается: `PUT` и `PATCH` возвращают `404`. Удаляйте редиректы по одному через `DELETE`; успешный ответ содержит `{"status":"ok"}`. Метода массового удаления нет.

Витрина отвечает `301` на адрес, который находится по правилам ниже. Редирект действует на запрос страницы. Адрес с суффиксом `.json` витрина по этим правилам не перенаправляет.

По умолчанию список содержит до 100 записей. У `per_page` нет нижней границы. Порядок записей не задан, поэтому одна запись может попасть на несколько страниц. При сборе списка увеличьте `per_page` или исключайте повторы по `id`.

`q[q]` ищет подстроку в старом и новом адресе. `q[c_from]` и `q[c_to]` ограничивают `created_at` по часовому поясу магазина.

### Создание

При сохранении старого адреса InSales удаляет схему и хост, оставляя путь. Например, `https://example.com/from-outside` сохраняется как `/from-outside`. Завершающий `/` также удаляется. При этом запрос витрины с завершающим `/` не совпадёт с сохранённым правилом.

Новый адрес на домене магазина также сохраняется как путь без завершающего `/`: `https://abc.myinsales.ru/catalog/` станет `/catalog`. Адрес другого сайта сохраняется целиком: `https://example.com/catalog`.

Одинаковые старый и новый адреса отвечают `422`, ключ `new_url`: «имеет неверное значение».

Нельзя создать редирект с корня `/` или с адреса, первый сегмент которого входит в список ниже. Для `/delivery` возвращается ошибка «Недопустимый URL. Путь '/delivery/' не может быть использован в качестве первой составной части старого URL.». Для корня в таком же сообщении указан путь `///`.

Запрещённый первый сегмент: `orders`, `cart_items`, `payments`, `auth`, `address`, `delivery`, `payment`, `fast_checkout`, `new_order`, `compares`, `cities`, `bank_receipts`, `yandex_market`, `yandex_snippets`, `torg_mail`, `sitemap`, `robots`, `juridical_person_receipts`, `yandex_market_fast_checkout`, `counter_settings`, `codes_settings`.

### Цепочки

При создании редиректа InSales проверяет, не образуется ли цепочка. Старый адрес новой записи не должен совпадать с новым адресом существующей, а новый адрес — со старым адресом другой записи. При совпадении API возвращает `422`.

«Уже существует редирект на адрес ...» — ключ `old_url`. «Уже существует редирект с адреса ...» — ключ `new_url`.

Чтобы объединить цепочку, передайте `remove_redirect_chains: 1`. InSales создаст новую запись и изменит конечный адрес существующих редиректов, которые вели на её старый адрес. Идентификаторы существующих записей сохранятся.

### Как витрина выбирает адрес

Пока среди редиректов нет старых адресов с `?`, InSales сравнивает только путь запроса и переносит параметры URL на новый адрес. Правило со знаком `?` в старом адресе в этом режиме не применяется.

При добавлении первого правила с `?` запрос `POST` может вернуть `500` без сохранения записи. При этом магазин переключается на точное сравнение адресов. Повторный такой же `POST` возвращает `201`.

В режиме точного сравнения должны совпасть и путь, и параметры URL. Параметры `domain` и `locale` отбрасываются. Параметры `_ga`, `tagtag_uid`, `erid`, `gsaid`, `advcake_params`, `utm_source`, `utm_medium`, `utm_campaign`, `yclid`, `ysclid`, `utm_referrer`, `utm_content` и `utm_term` не влияют на совпадение и переносятся на новый адрес.

Параметр `page` влияет на сравнение: адрес с `page` не совпадёт с правилом без параметров URL.

Знак `*` в конце старого адреса позволяет сопоставить этот путь как с параметрами URL, так и без них. Более длинные пути с правилом не совпадают. Регулярные выражения не поддерживаются.

Повторяющиеся слэши в пути заменяются одним, даже если для адреса нет отдельного редиректа. Например, `/foo//bar` перенаправляется на `/foo/bar`.

В таблице цель цепочки — `/docs-api-final`. В колонке «точный режим» среди редиректов есть старый адрес с `?`. В колонке «только путь» таких редиректов нет.

| Запрос | Точный режим | Только путь |
| --- | --- | --- |
| `/docs-api-old` | `/docs-api-final` | `/docs-api-final` |
| `/docs-api-old?utm_source=ads` | `/docs-api-final?utm_source=ads` | `/docs-api-final?utm_source=ads` |
| `/docs-api-old?page=2` | совпадения нет | `/docs-api-final?page=2` |
| `/docs-api-q?color=red` | `/docs-api-final` | правило с `?` не используется |
| `/docs-api-q?color=blue` | совпадения нет | правило с `?` не используется |
| `/docs-api-q?utm_source=ads` | совпадения нет | правило с `?` не используется |
| `/docs-api-wild` и `/docs-api-wild?x=1` | `/docs-api-final` | `/docs-api-final`, query дописывается |
| `/docs-api-wild/extra` | совпадения нет | совпадения нет |
| `/page/docs-api-page?utm_source=ads&page=2` | совпадения нет | `/docs-api-final?utm_source=ads&page=2` |
