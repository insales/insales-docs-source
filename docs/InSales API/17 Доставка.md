# Доставка и точки самовывоза

Способы доставки и точки самовывоза можно читать и менять, если у приложения есть право на настройки магазина.

Если этого права нет, ответ `403`:

```json
{"status":"error","message":"Недостаточно прав для операции"}
```

## Доставка

`GET /admin/delivery_variants.json` возвращает все способы доставки магазина, отсортированные по `position`. Для чтения одного способа используйте `GET /admin/delivery_variants/:id.json`. Чтобы получить несколько способов, прочитайте общий список или запросите каждый отдельно.

Метод `GET /admin/delivery_variants/by_ids.json` не поддерживается: он возвращает `404` с HTML-страницей. Такой же ответ возвращается для несуществующего идентификатора.

В общем объекте есть `id`, `position`, `title`, `description`, `type`, `charge_up_to`, `inverted`, `show_zip_code`, `min_order_sum`, `payment_delivery_variants`, `delivery_locations`, `delivery_time_intervals`, `created_at`, `updated_at`. Для типов с датой доставки объект также содержит `show_calendar_in_checkout`, `delivery_date_required`, `forbid_weekends`, `utc_from_address`, `estimated_delivery_period`, `order_time_is_later`, `forbidden_days`, `show_time_intervals_in_checkout`, `time_intervals_required`.

Массив `payment_delivery_variants` содержит связи со способами оплаты. Покупателю доступны только способы оплаты, связанные с выбранной доставкой. Чтобы при создании привязать все существующие способы оплаты, передайте `add_payment_gateways: true`. Это поле не возвращается в ответе.

`min_order_sum` в ответе есть. Передача `1000` в теле создания оставляет в объекте `null`.

Поле `delivery_locations` содержит города и регионы, для которых доступен способ доставки. При сохранении передавайте их в `delivery_locations_attributes` — массиве или объекте с числовыми ключами.

Для каждой локации обязательны `country` и `region`. Значение `city: null` распространяет локацию на весь регион. Например, `обл Ленинградская` при `city: null` сохраняется без изменения. Если передать город без региона, API вернёт `422`:

```json
{"delivery_locations.sanitized_region_name": ["Не заполнены обязательные поля"]}
```

Неизвестное имя региона сохраняется как передано. Удаление локации — тот же массив с `id` и `_destroy: 1`.

У доставки «от локации» тарифные зоны задаются в `delivery_zones`. Города каждой зоны передаются во вложенном `locations_attributes`. Поле `delivery_locations_attributes` у этого типа меняет отдельный список доступных локаций и не изменяет зоны.

Тип вне списка, например `DeliveryVariant::Unknown` или `DeliveryVariant::NovaPoshta`, отвечает `422`. Текст ошибки — отсутствующий перевод `not_in_variants_list`.

В списке магазина встречаются и другие типы. `DeliveryVariant::None` тоже хранит `price`. `DeliveryVariant::NoDelivery` — способ «доставка не требуется», у него нет полей даты доставки. Точки самовывоза относятся к `DeliveryVariant::PickUp`, а не к способу с названием «Самовывоз», если у того другой `type`.

`DELETE /admin/delivery_variants/:id.json` отвечает `200` и `{"status":"ok"}`.

### Дата и интервалы

Для фиксированной доставки, внешней доставки, доставки от локации, доставки от суммы и самовывоза можно настроить календарь и интервалы времени. Передайте интервалы строкой в `time_intervals`, разделяя пары часов запятыми: `10-14,14-18`. В ответе InSales вернёт разобранный массив `delivery_time_intervals`. У каждого интервала есть `time_from`, `time_to` и признаки дней недели; для такой строки все семь признаков равны `true`.

Повторная запись `time_intervals` не заменяет сохранённые интервалы. При этом флаги календаря изменяются: `show_calendar_in_checkout`, `estimated_delivery_period`, `forbidden_days`, `delivery_date_required`, `forbid_weekends`, `order_time_is_later`, `show_time_intervals_in_checkout` и `time_intervals_required`.

Часы вроде `10:00-14:00` отвечают `422`:

```json
{"time_intervals": ["Некорректный формат! Пример: 10-14, 14-18, 18-22\n"]}
```

### Внешняя

Способ `DeliveryVariant::External` получает расчёт стоимости от сервиса по адресу `url`. Чтобы выбрать вторую версию протокола, передайте `api_version: v2`. Пустое значение включает первую версию. Поле `api_version` не возвращается в ответе, поэтому сохраняйте выбранную версию в приложении. Поля `javascript` и `customer_pickup` возвращаются; `javascript` сохраняется строкой.

Для непубличного URL сервиса API возвращает `422` и тело `{"url":["Недопустимый URL"]}`.

В первой версии InSales отправляет GET-запрос на `url`, добавляя параметры `price` (сумма товаров со скидкой), `weight`, `region`, `city`, `zip`, `kladr_code`, вложенный `location` и `callback=external`. Дополнительные поля заказа и адреса не передаются.

Сервис должен вернуть текст с вызовом `external(...)`, внутри которого находится JSON с `delivery_price`. Для ошибки используйте `error` или массив `errors`. Строка `Current carrier is not available!` делает способ недоступным. InSales ожидает ответ не более 4 секунд.

Во второй версии InSales отправляет POST-запрос на `url` с заголовком `Content-Type: application/json; charset=UTF-8` и телом `{"order": ...}`. Объект `order` содержит `account_id`, `currency_iso_code`, `delivery_variant_id`, `warehouse_id`, `items_price`, `total_weight`, адрес `shipping_address` (`full_locality_name`, `delivery_address`, `location`) и строки `order_lines` (`product_id`, `variant_id`, `quantity`, `weight`, `dimensions`). Дополнительные поля заказа не передаются.

Сервис должен вернуть JSON-массив тарифов. У каждого тарифа InSales читает `price`, `tariff_id`, `title`, `description`, `delivery_interval`, `shipping_company`, `shipping_company_handle`, `warnings`, `errors`, `fields_values` и `outlet`. Пустой массив, невалидный JSON или HTTP-ошибка означают, что стоимость не рассчитана. InSales ожидает ответ не более 6 секунд. При повторном расчёте среди нескольких тарифов магазин ищет ранее выбранный по `tariff_id`.

`outlet` в тарифе второй версии — пункт выдачи: адрес и описание приходят из ответа сервиса. Пустые `address` и `description` в заказе означают, что сервис прислал их пустыми.

Выбранный тариф записывается в заказ ключом `order[delivery_info_attributes]`. В объекте сохраняются `tariff_id`, `price`, `title`, `shipping_company_handle`, `delivery_interval` и `outlet`. В заказе они возвращаются в `delivery_info`. Создание заказа описано в [заказах](12%20Заказы%20и%20клиенты.md).

### От локации

`DeliveryVariant::LocationDepend` требует хотя бы одну зону. Пустой способ отвечает `422`, тело `{"delivery_zones":["не может быть пустым"]}`.

У зоны есть название `title`, массив тарифов `tariffs_attributes` и массив локаций `locations_attributes`. Для тарифа обязательны `max_weight`, `price`, `step` и `step_price`.

Поля `step` и `step_price` задают доплату за каждый следующий шаг веса после `max_weight`. Если их не передать, API вернёт `422` с сообщениями «Не заполнены обязательные поля» и «не является числом» для обоих полей.

### От суммы

Для `DeliveryVariant::PriceDepend` обязательно поле `min_price` — стоимость доставки, если ни одно правило не подошло. Правила передаются в `rules_attributes`. У каждого правила `order_price` должен быть строго больше нуля. Нулевой порог отклоняется со статусом `422` и телом `{"rules.order_price":["Стоимость заказа должна быть больше нуля"]}`.

Вместе с порогом суммы можно указать `order_weight`. Поле `price` задаёт стоимость доставки при достижении порога.

### Самовывоз

При создании `DeliveryVariant::PickUp` InSales также создаёт способ оплаты `PaymentGateway::PickUp` с названием «Оплата в точке самовывоза», если его ещё нет. В ответе создания связь с этой оплатой может отсутствовать; проверьте её следующим GET-запросом. Для чтения и создания точек используйте методы раздела [«Точки самовывоза»](#точки-самовывоза).

Точка внешнего пункта передаётся в заказ тем же `order[delivery_info_attributes]`, внутри `outlet`. Для этого типа у точки нужны `latitude` и `longitude`. Без координат ответ `422`:

```json
{
  "delivery_variant_id": ["Не выбрана точка самовывоза"],
  "base": ["Не выбрана точка самовывоза"]
}
```

С координатами заказ сохраняется, а `delivery_info.outlet` содержит `id`, `external_id`, `latitude`, `longitude`, `title`, `address` и `source_id`.

В объекте есть пустые массивы `pick_up_sources` и `pick_up_source_delivery_variants`.

## Точки самовывоза {#точки-самовывоза}

`GET /admin/outlets.json` возвращает точки самовывоза способов `DeliveryVariant::PickUp`. Если точек нет, ответ содержит `[]`. При создании точки InSales находит способ этого типа. Если его нет, InSales создаёт способ «Доставка в точки самовывоза».

Обязательны `title`, `address`, `price` и пара координат `latitude`, `longitude`. Цена ноль допустима.
