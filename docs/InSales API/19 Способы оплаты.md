# Способы оплаты

Способы оплаты можно читать и менять, если у приложения есть право на настройки магазина. Нужно ещё право на внешние оплаты.

Если нужного права нет, ответ `403`:

```json
{"status":"error","message":"Недостаточно прав для операции"}
```

## Способы оплаты {#способы-оплаты}

`GET /admin/payment_gateways.json` отдаёт способы оплаты по `position`. `GET /admin/payment_gateways/:id.json` — один способ. Неизвестный id — `404` и HTML-страница.

В объекте есть `id`, `type`, `position`, `title`, `description`, `margin`, `available_for_individual_clients`, `available_for_juridical_clients`, `payment_delivery_variants`, `created_at`, `updated_at`. `margin` — наценка в процентах, строка вроде `"0.0"`. Связь `payment_delivery_variants` указывает `delivery_variant_id`: без неё способ в чекауте для этой доставки не показывается.

`add_delivery_variants: true` при создании привязывает все текущие доставки. Одна доставка передаётся массивом `payment_delivery_variants_attributes` с `delivery_variant_id`. Оба флага сразу не обязательны: достаточно одного массива.

Название уникально в магазине. Повтор — `422`, тело `{"title":["уже существует"]}`. Оба флага клиентов `false` — `422`, тело `{"client_types":["Не задан тип клиента"]}`. Тип вне списка, например `PaymentGateway::YandexMoney`, отвечает `500` и HTML-страницей.

`PUT` меняет название, описание, наценку, флаги клиентов и связи с доставками. Связь удаляется элементом с `id` и `_destroy: 1`. Новая связь — элемент с `delivery_variant_id`. Оба действия в одном теле выполняются вместе.

`DELETE /admin/payment_gateways/:id.json` отвечает `200`, тело пустое.

Протокол `PaymentGateway::External` — в [статье о внешнем способе](02%20Подключение%20внешнего%20способа%20оплаты%20(для%20разработчиков%20интеграций).md). Создание этого типа тем же `POST` отвечает `201` и добавляет `url`, `shop_id`, `password`, `send_order`, `success_url`, `fail_url`, `server_url`.

### Наложенный платёж

`PaymentGateway::Cod` — оплата при получении. Отдельного URL оплаты нет.
