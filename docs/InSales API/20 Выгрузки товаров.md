# Выгрузки товаров

Выгрузки можно читать и менять, если у приложения есть право на маркетплейсы.

Если этого права нет, ответ `403`:

```json
{"status":"error","message":"Недостаточно прав для операции"}
```

## Выгрузки товаров {#выгрузки-товаров}

`/admin/marketplaces` — файл товаров для внешней площадки. Каталог приложений к этому адресу не относится. `id` в пути — число. `GET /admin/marketplaces/abc.json` — страница `404` витрины.

Поле `url` — адрес файла без Basic. `Content-Type` XML-файла — `application/xml; charset=utf-8`. Ссылки внутри файла используют хост, с которого файл запрошен. Если запрошенный язык в магазине не включён, `?lang=` возвращает тот же файл. `?download=1` при сборке файла на лету заголовок скачивания не ставит.

`GET /admin/marketplaces.json` отдаёт массив. Набор полей зависит от `type`. `collection_ids` в ответе `201` может быть `[]`, хотя идентификаторы сохранены: следующий `GET` их показывает.

В файл попадают товары выбранных коллекций. Пустой список коллекций и пустая коллекция дают файл без товаров. Архивный товар из файла пропадает. Товар вне выбранных коллекций в файл не входит.

Смена `type` у существующей записи запросом `PATCH` отвечает HTML `404`, и тип в записи уже другой. Новую площадку создают отдельным `POST`.

`DELETE /admin/marketplaces/ID.json` отвечает `200`, тело `{"status":"ok"}`.

### Какие типы создаются одним названием

Тело с `name` и `type`. Неизвестная строка типа отвечает `422`, тело `{"type":["Тип является обязательным полем"]}`. Тело только с `name`, без `type`, отвечает `500` и HTML-страницей. Повтор `name` в магазине отвечает `422`, тело `{"name":["Выгрузка с таким названием уже существует"]}`. Пустое название отвечает `422`, тело `{"name":["Не указано название выгрузки"]}`.

| type | Ответ на name и type |
| --- | --- |
| `Marketplace::GoogleMerchant` | 201, файл `.xml` |
| `Marketplace::ExcelPrices` | 201, `url` заканчивается на `.xls` |
| `Marketplace::LiquidYandexMarket` | 201, в ответе шаблон `offer_liquid` по умолчанию |
| `Marketplace::ModelYandexMarket` | 422: пустые `shop_name`, `shop_company`, `vendor_id` |
| `Marketplace::YandexMarket` | 422: пустые `shop_name`, `shop_company` |
| `Marketplace::Sbermegamarket` | 422: пустые `shop_name`, `shop_company` |
| `Marketplace::CartsLiquidYandexMarket` | 422: `touched_carts_days_ago` должен быть от 0 до 30 |
| `Marketplace::Avito` | 422: пустые `address` и `category_id`, плюс непринятые `listing_fee`, `ad_status`, `condition_type` |

### Google Merchant

Достаточно названия и типа. `description_type` принимает 1 и 2. `adult`, `utm_label`, `local_delivery_cost` и `collection_ids` сохраняются и возвращаются. Отрицательная стоимость доставки отвечает `422`, тело `{"local_delivery_cost":["Стоимость доставки должна быть неотрицательным числом, например 300"]}`.

`brand` принимается и влияет на файл, в JSON записи его нет. `not_load_not_available`, `show_hidden` и `layout_template` в JSON тоже не возвращаются.

### Яндекс.Маркет, модель

`shop_name` короче 21 символа. Длиннее отвечает `422`, тело `{"shop_name":["Название магазина не может быть длиннее 20 символов."]}`. `vendor_id` — `id` параметра товара. Чужой `id` отвечает `422`, тело `{"vendor_id":["Такого параметра для указания производителя не существует"]}`.

Успешное создание возвращает `collection_ids: []`. Категории уже есть в файле, а следующий `PUT` без повторной передачи коллекций возвращает их список. Дата в файле модели — время магазина со смещением.

### Произвольный шаблон

`Marketplace::LiquidYandexMarket` без `offer_liquid` отвечает `201` и записывает шаблон оффера по умолчанию. В нём есть `product.id`, `product.price`, `product.title`, `product.properties.vendor`, `account.url`, `collection.id`. Ошибочный Liquid отвечает `422`, например `{"offer_liquid":["Offer liquid содержит ошибку: Liquid syntax error (line 1): 'if' tag was never closed"]}`.

В шаблоне оффера доступны `product`, `account` и `collection`: `product.id`, `product.title`, `product.price`, `product.cost_price`, `product.sku`, `product.currency_id`, `product.available`, `product.variants.first.id`, `product.variants.first.cost_price`, `account.url`, `collection.id`, `collection.title`. Закупочная цена печатается и как `product.cost_price`, и как `product.variants.first.cost_price`, когда она заполнена у варианта.

Параметр товара печатается по permalink и по названию: `product.properties.brand` и `product.properties['Бренд']`. Имя `vendor` остаётся пустым, пока нет параметра с таким permalink или названием. Параметр попадает в шаблон после выбора в выгрузке. Выбор передаётся объектом с числовыми ключами.

Вокруг оффера стандартная обёртка `yml_catalog`: категории, валюта `RUB`, пустой блок акций.

`product.fields.HANDLE` — строка выбранного доп. поля, без `.value`. Пока поле не выбрано, подстановка пустая. Запрос с `marketplace_product_fields_attributes` отвечает `422`:

```json
{
  "marketplace_product_fields.account_id": ["Не заполнены обязательные поля"],
  "marketplace_product_fields.product_field": ["Не заполнены обязательные поля"]
}
```

`{% for product in products %}` в шаблоне оффера товаров не перебирает. Общая обёртка файла задаётся `layout_template`. В ней есть `content_for_layout` — уже собранные офферы, `marketplace.shop_name`, `marketplace.company`, `account.url`, `currency`. Переменной `products` в обёртке нет. `layout_template` в JSON записи не возвращается, файл при этом собирается по нему. Фильтр `{{ 'now' | date: '%Y-%m-%d %H:%M' }}` печатает время UTC: при магазине `+03:00` в файле было `2026-10-21 19:36`. Дата стандартной обёртки модели Яндекса при этом остаётся во времени магазина.
