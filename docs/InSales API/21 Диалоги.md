# Диалоги

Ключ с правом на диалоги и полным доступом выпускает токен канала. Без права `POST /admin/dialogs/provider_tokens.json` отвечает `403`. У опубликованного приложения это право в кабинете партнёра не выдаётся, и ответ тот же. Дальше провайдер работает с Provider API на `messengers.insales.ru`.

## Токен провайдера диалогов

Один метод: `POST /admin/dialogs/provider_tokens.json`. `GET` этого адреса отвечает `404`. Тело — верхний уровень, поле `messenger_type`. Обёртка `provider_token` игнорируется и отвечает тем же телом, что и пустой запрос.

Рабочие значения: `sms`, `telegram`, `viber`, `email`, `vk`. `sms` — канал «Диалогов». Код входа на витрину этим методом не выпускается.

Ответ успеха — `200` и два значения по 128 шестнадцатеричных символов. Повтор для того же `messenger_type` выпускает новую пару, старая перестаёт подходить к Provider API. Ошибки этого метода тоже приходят с `200` и полем `error`.

Удаление пароля приложения удаляет его токены. Прежний `api_token` после этого отвечает `401`.

### Provider API

Хост — `https://messengers.insales.ru`. Заголовок `Authorization` равен `api_token`, без `Basic` и без `Bearer`. Чужой токен отвечает `401`, тело `{"error":"Not authorized"}`.

Пока магазин не переключил канал на этого провайдера, `active` равен `false`. Вызов, который переключает канал, в Provider API нет.

На `send_message_url` магазин шлёт `POST` с `Authorization: webhook_token` и `Content-Type: application/json`. Текстовое сообщение:

```json
{
  "to": "chat-id",
  "internal_id": 100,
  "account_id": 233686,
  "body": "текст",
  "type": "text"
}
```

Файл вместо `body` и `type: text` приходит как `type: file` и `files: [{url, name}]`. Ответ сервиса — `200` и JSON со `status` и `external_id`. Статусы: `scheduled`, `wait_for_capture`, `complete`, `error`. Другой HTTP-статус и неизвестный `status` считаются ошибкой. Повторной отправки вебхука нет.

На `settings_url` тем же заголовком уходит `{"gateway_token":"…","account_id":233686}`, когда у магазина меняется токен шлюза.

Входящее сообщение клиента провайдер передаёт своим `POST /api/messengers/provider/v1/messages`. Пока `active` равен `false`, ответ `422`.
